# DateCourseApp

출발 위치·원형 범위·인원을 정한 뒤, 장소마다 활동·가격 상한·이동 반경을 설정해 코스를 구성하는 Java 데스크톱 앱입니다. 총예산은 따로 입력하지 않고 편집 화면에서 누적 예상 금액을 확인합니다. 편집 완료 시 메인 지도에 반영하며, 로그인 앱에서 코스 저장·회원별 목록·다시 열기·수정 저장·이름 변경·삭제를 연결했습니다. 실제 MySQL 수동 검증은 남아 있습니다.

최신 UI는 [홈 메뉴와 공통 UI](docs/공통_UI와_홈_메뉴.md)를 참고하세요. 헤더에서 페이지를 이동하고 저장 시 이름을 입력합니다. 기존 저장·수정·재시작 복원은 사용자 수동 확인을 마쳤고, 이번 공통 UI 변경의 실제 실행 확인은 별도입니다.

## 현재 구현 상태

### 시연 목록과 가격 상태 확인

회원 DB 없이 `.\gradlew.bat runPilotDemo`로 서면·전포 9곳을 확인할 수 있습니다. 일반 앱에서는 왼쪽 **장소 목록**에서 기존 목록과 시연 목록을 선택합니다. 현재 시연 9곳은 1인 가격 미확인이므로 편집 화면에서 **가격 미확인·상한 미확인 장소도 포함**을 선택해야 후보가 표시됩니다. 금액을 임의로 넣거나 미확인을 무료로 계산하지 않습니다.

가격 범위가 있으면 **예상 총비용 범위**, 일부가 미확인이면 **확인된 비용 + 가격 미확인 N곳**으로 표시합니다. 실행 확인·코드 읽는 순서·저장 준비는 [시연 장소와 가격 흐름](docs/시연_장소와_가격_흐름.md)을 참고하세요.

| 기능 | 상태 |
|---|---|
| 시작 로딩 | 백그라운드 DB 초기화, 성공 시 로그인 전환, 실패 시 재시도·종료 |
| 회원가입 | 이메일·비밀번호·확인·이름·전화번호 순서로 입력 및 DB 저장 |
| 로그인 | 실제 DB 인증, 비활성 회원 차단, 조건 입력 화면으로 전환 |
| 아이디 저장 | 체크 후 로그인 성공 시 한 개 저장, 다음 실행 시 자동 입력 |
| 사용자 세션 | 회원 ID·이름을 보관하고 조건 입력 컨트롤러에 전달 |
| 장소 적재 | 6,139건을 최대 250건씩 묶어 INSERT, 진행 상황 표시 |
| 장소 조회 | 기존 DB 목록 또는 자체 ID·출처를 담은 서면·전포 시연 목록 9곳을 선택 |
| 거리·비용 계산 | 미터 단위 반경 필터, 가격 범위 합계·미확인 장소 수를 구분 |
| 지도 | JavaFX WebView에 카카오 지도 표시, 부산시청 부근에서 시작 |
| 출발 장소 검색 | 카카오 장소 검색, 부산 주소 결과만 표시, 선택 시 지도 이동·마커 표시 |
| 위치·반경 선택 | 지도 클릭 또는 검색 결과로 실제 위도·경도 선택, 반경 200~2,000m 표시 |
| 선택 위치 안내 | 검색 결과는 장소명, 직접 찍은 위치는 주소 표시. 주소 조회 실패 시 ‘선택한 위치’ 표시 |
| 조건 입력 UI | 공통 조건 → 장소별 편집 화면으로 슬라이드 전환. 우측은 Condition(조건)·Choice(후보) 중 하나만 펼치며, 진입 버튼은 코스 만들기 / 코스 편집 |
| 장소 가격 입력 | 1인 가격 상한을 만원 단위로 입력. 화살표 버튼·방향키·마우스 휠 조절 |
| 주변 장소 | 로그인 연결 풀로 백그라운드 조회, 추천 요청 전에는 주변 목록·마커 숨김 |
| 장소별 추천·편집 | 출발지 중심 전체 원형 범위와 마지막 장소 기준 반경·활동·1인 가격 상한을 적용해 거리순 상위 최대 5곳 표시, 선택한 1곳 추가·삭제·순서 변경 |
| 편집 지도 | 왼쪽 55%의 별도 지도, 확정 장소·후보 구분, 현재 범위·전체 코스 맞춤. 편집 완료 전 메인과 상태 분리 |
| 편집 완료·취소 | 완료 시 메인 코스·지도 반영, 취소 시 편집본 폐기. 앱 종료 후 코스 유지 기능은 없음 |
| 상세 정보 | 후보 상세·코스 장소 상세 버튼, 목록 더블클릭, 두 지도의 장소 마커로 열기. 분류·1인 가격·있는 경우 평점·카카오맵 링크 표시 |
| 코스 저장 | 로그인 앱 헤더에서 저장·본인 목록·다시 열기·수정 저장·이름 변경·삭제. H2/FXML 자동 검사, 실제 MySQL 수동 검증 필요 |
| 커뮤니티·관리자 | 기존 화면·처리 코드가 남아 있으나 통합 흐름은 미완성 |

현재 MemberRepository.login()은 일반 회원 인증만 처리합니다. app_admins 초기화와 관리자 화면 코드는 남아 있지만 관리자 인증 분기가 없어, 관리자 계정으로 화면에 진입하는 기능은 동작하지 않습니다.

## 개발 환경과 실행

- 빌드·실행 기준: Gradle Wrapper
- 현재 빌드 검증 환경: Temurin JDK 21, Gradle 9.6.0
- 화면: Swing 및 JavaFX 21 (controls, fxml, web, swing)
- DB: MySQL 호환 서버. 로컬 MySQL 또는 Aiven for MySQL 접속 정보 사용
- 주요 라이브러리: MySQL Connector/J, HikariCP, Jackson
- 테스트: JUnit 5, H2
- 지도 웹 서버: Java 앱이 8080 포트에서 자동 시작 (별도 Python 실행 불필요)

다른 JDK를 사용할 때는 JavaFX 21과 Gradle Wrapper의 호환성을 확인해야 합니다. 예전 Maven 설정은 `docs/archive/pom.xml`에 참고용으로 보관했으며 현재 앱의 빌드·실행은 Gradle을 기준으로 합니다.

먼저 아래 **DB 준비**와 **카카오 지도 준비**를 마친 뒤 프로젝트 루트에서 앱을 실행합니다. 지도 화면을 열면 앱이 로컬 지도 서버를 자동으로 시작합니다.

~~~powershell
.\gradlew.bat run
~~~

IntelliJ에서는 com.datecourse.app.AppLauncher.main()을 실행하거나 Gradle의 run 작업을 사용합니다. 실행 설정의 Working directory는 프로젝트 루트로 지정합니다.

~~~text
AppLauncher
  → MembershipApp
  → 시작 로딩 / DB 초기화
      ├─ 실패 → 다시 시도 또는 종료
      └─ 성공 → 로그인
                  ├─ 회원가입 → 가입 완료 → 로그인
                  └─ 로그인 성공 → 조건 입력 / 부산 지도
                                      → 검색 또는 지도 클릭으로 출발 위치 선택
                                      → 인원·전체 원형 범위 설정
                                      → 코스 만들기 / 코스 편집
                                          → 별도 지도와 장소별 조건 화면으로 슬라이드 전환
                                          → 거리순 후보 최대 5곳 → 상세 확인·선택 → 코스에 1곳 추가
                                          → 다음 장소 선택 / 삭제·순서 변경 반복
                                          ├─ 편집 완료 → 메인 코스·지도에 반영
                                          └─ 취소 → 마지막 확정본 유지
~~~

com.datecourse.app.MainApp은 이전 실행 코드이며 현재 저장소에 없는 /fxml/Login.fxml을 참조합니다. 통합 앱은 AppLauncher로 실행합니다.

## 팀 공통 API 설정 (권장)

[공통 접속 키 설정 안내](docs/공통_접속_키.md)에 따라 `.local/team-access.properties`에 접속 키 하나만 입력합니다. 카카오·TMAP·Google 키는 서버에서 받아 메모리에 보관합니다. DB 접속 정보도 같은 공통 키로 받아옵니다. 카카오 허용 도메인은 계속 필요합니다. 공통 설정을 사용하면 아래 개별 API 키 입력은 생략합니다. 실제 TMAP 키와 `db.properties`는 빌드 결과에 포함하지 않습니다.

## 카카오 지도 준비

### 1. JavaScript 키와 도메인 설정

1. [Kakao Developers](https://developers.kakao.com/)에서 앱을 생성하거나 사용할 앱을 선택합니다.
2. 앱의 카카오맵 사용 설정을 활성화하고 **JavaScript 키**를 준비합니다.
3. 해당 JavaScript 키의 SDK 허용 도메인에 **`http://localhost:8080`**을 등록합니다. 키와 도메인 등록 절차는 [카카오 지도 공식 가이드](https://apis.map.kakao.com/web/guide/)를 참고합니다.
4. [kakao-config.example.js](src/main/resources/map/kakao-config.example.js)를 같은 폴더의 `kakao-config.js`로 복사하고 JavaScript 키를 입력합니다.

~~~powershell
Copy-Item src/main/resources/map/kakao-config.example.js src/main/resources/map/kakao-config.js
~~~

~~~javascript
window.KAKAO_MAP_KEY = "YOUR_KAKAO_JAVASCRIPT_KEY";
~~~

실제 `kakao-config.js`는 Git과 애플리케이션 JAR에서 제외하며 실행할 때 읽습니다. 빈 예제 파일만 공유합니다. REST API 키나 관리자 키를 넣지 않습니다. 공통 접속 키가 없을 때는 비어 있지 않은 환경변수 `KAKAO_MAP_JAVASCRIPT_KEY`가 우선합니다. 소스 설정 파일에 키가 없으면 `.local/kakao-map.properties`의 `kakao.javascript.key`를 읽으므로 배포본에서도 이 로컬 파일을 사용할 수 있습니다.

### 2. 지도 페이지 실행

앱의 지도 화면이 **`http://localhost:8080/map.html`**을 자동으로 엽니다. DB나 로그인 없이 지도만 확인하려면 아래 명령으로 실행합니다.

~~~powershell
.\gradlew.bat runMapDemo
~~~

- `localhost`와 `127.0.0.1`은 도메인 등록에서 서로 다른 호스트입니다. 현재 앱과 동일하게 `localhost` 주소로 확인합니다.
- 서버는 `127.0.0.1`에만 바인딩하고 지도 HTML·JS·CSS와 키 설정 응답만 제공합니다. 프로젝트의 다른 파일은 제공하지 않습니다.
- 메인 지도와 코스 편집 지도가 서버 하나를 공유하며 앱 종료 시 정리됩니다. 이전에 수동으로 실행한 Python 서버가 있다면 종료합니다. 다른 앱이 8080 포트를 사용하면 오류 안내가 표시됩니다.
- 키를 수정하거나 연결에 실패했을 때 메인 화면 또는 편집 화면의 **지도 다시 불러오기**를 누릅니다. 현재 선택 위치와 코스는 유지됩니다. SDK 응답이 20초 동안 없으면 연결 시간 초과를 안내합니다.

### 3. 지도 사용 흐름과 제한

- 검색창에 `서면역`, `부산역`, `광안리` 등을 입력하면 공백이 아닌 검색어 변경 후 300ms 뒤 자동 검색합니다. Enter 또는 검색 버튼으로 즉시 검색할 수도 있습니다.
- 자동완성 목록과 안내 메시지는 검색창 아래에서 지도 위를 덮는 오버레이로 표시하며, 표시·숨김 시 지도 크기와 중심을 변경하지 않습니다. 위·아래 방향키로 결과 버튼에 실제 포커스를 이동하고 Enter로 출발 위치를 확정합니다. 첫 결과에서 위 방향키를 누르거나 Esc로 닫으면 검색창으로 돌아갑니다. 한글 조합 중 방향키·Enter는 가로채지 않습니다.
- 검색 결과를 선택하면 지도 중심·마커·반경이 이동하고 해당 좌표가 Java 컨트롤러에 전달됩니다.
- 검색은 DB가 아닌 **카카오 장소 검색 서비스**를 사용합니다. 부산 검색어를 적용하고 응답 중 부산 주소인 결과만 표시합니다.
- 지도에서 직접 출발 위치를 찍을 수도 있습니다. 이 경우 좌표로 주소를 조회해 하단에 표시합니다.
- 결과 목록은 선택 후 닫히며, 닫기 버튼이나 Esc로도 닫을 수 있습니다.
- 카카오 로고와 관련 웹 링크는 앱의 지도 화면 대신 기본 브라우저로 연결합니다.
- **GPS·자동 현재 위치 조회 기능과 C# 보조 프로그램은 사용하지 않습니다.** .NET SDK나 런타임은 필요하지 않습니다.
- 부산을 서비스 대상으로 개발 중이지만, 지도 이동·직접 클릭을 부산 행정구역 안으로 제한하는 검증은 아직 없습니다.
- 메인 화면은 출발 위치·인원·루트 전체 원형 범위를 설정하는 공통 조건 화면입니다. 추천 전에는 주변 장소 목록·마커를 표시하지 않습니다.
- 하나의 ‘코스 만들기 / 코스 편집’ 버튼으로 같은 창의 편집 화면에 슬라이드 전환합니다. 왼쪽 약 55%는 별도의 편집 지도, 오른쪽은 코스 목록과 장소별 조건입니다.
- 총예산은 입력하지 않으며 편집 화면에서 인원 기준 누적 예상 금액을 확인합니다. 장소별 1인 가격 상한은 **만원 단위 정수**입니다. 화살표 버튼·키보드 위아래·마우스 휠로 1만원씩 조절합니다. 장소 가격 상한 0은 무료 후보만 허용합니다.
- 장소마다 활동·1인 가격 상한·이전 위치로부터 탐색 반경을 설정합니다. 첫 장소는 출발지, 이후는 마지막 확정 장소를 기준으로 거리순 추천합니다. 이미 추가한 장소와 출발지 중심의 전체 원형 범위 밖에 있는 후보는 제외합니다. 총예산 제한은 적용하지 않습니다. 장소를 추가할 때 이동 반경을 RoutePlan에 보관하며, 순서 변경·삭제·재편집 시 구간별 실제 거리와 허용 거리를 표시하고 초과하면 편집 완료를 차단합니다. 다음 장소 반경 슬라이더는 이미 추가한 장소의 조건을 변경하지 않습니다. 편집 완료 후 헤더에서 코스 저장을 누르면 장소별 이동 반경도 DB에 보관합니다.
- 추천 시 조건에 맞는 후보를 이전 위치에서 가까운 순으로 최대 5곳 표시합니다. 목록에서 한 곳을 선택하고 ‘선택한 장소 추가’를 눌러야 편집 코스에 들어갑니다. 후보가 5곳보다 적으면 있는 후보만 표시하며, 평점순 추천은 적용하지 않습니다. 같은 ID 또는 같은 이름·좌표인 중복 행은 제거하며, 중복 중 낮은 가격을 대표값으로 사용합니다. 가격의 정확성은 별도 데이터 검증이 필요합니다.
- 추가·삭제·순서 변경은 편집 지도에 즉시 반영되지만 현재 중심·확대 수준은 유지합니다. 범위 변경·편집 진입 또는 명시적인 지도 맞춤 버튼에서만 범위를 자동 조정합니다. 편집 지도에서 전체 원형 범위는 파란 실선, 마지막 장소 기준 범위는 초록 점선으로 표시합니다. 후보는 두 범위의 교집합에서만 고릅니다. 첫 장소는 두 범위 모두 출발지 기준입니다. ‘두 범위 보기’는 두 원 전체를, ‘전체 코스’는 출발지·코스·후보 전체를 지도 안에 맞춥니다. 메인 지도는 전체 원형 범위만 표시합니다. 지도 내 별도 장소 목록은 표시하지 않습니다.
- ‘편집 완료’에서만 메인 코스·지도를 갱신하며, 메인 지도도 선택한 원형 범위 전체가 보이도록 맞춥니다. ‘취소’는 편집본을 버리고 마지막 확정본을 유지합니다. 완료는 DB 저장이 아니며 앱 종료 후 보관·회원별 재조회는 아직 지원하지 않습니다. 장소를 모두 삭제해도 완료할 수 있으며, 취소 버튼은 편집 취소하고 돌아가기로 표시합니다. 빈 코스 반영 후 메인 버튼은 코스 만들기로 표시합니다.
- 우측 패널은 **Condition / Choice** 두 상태입니다. 처음에는 Condition에서 활동·가격·반경을 고르고 후보 목록은 접습니다. 추천 성공 시 조건을 접고 Choice의 후보를 펼칩니다. ‘조건 수정’은 입력값을 유지해 Condition으로 돌아가며, 실제 조건 변경 시 기존 후보를 비웁니다. 장소 추가·삭제·순서 변경 후에는 Condition으로 돌아가 마지막 장소를 기준으로 다음 후보를 고릅니다. 추천 결과가 없거나 입력이 잘못되면 Condition을 유지합니다.
- 누적 금액은 상단에 고정하고 코스 이름·장소 목록·순서 변경은 접이식 ‘내 코스 보기’에 둡니다. 장소별 간략 정보에는 1인 가격과 전체 인원 기준 비용을 함께 표시합니다. 내 코스에서 장소를 선택하면 해당 장소의 실제 이동 거리와 허용 반경을 확인하고, 전용 슬라이더로 200~2000m를 100m 단위로 수정할 수 있습니다. 즉시 재검사하며 다음 장소 조건·추천 후보·지도 시점은 유지합니다. 이동 반경 미기록 장소는 명시적으로 500m를 기록하거나 슬라이더를 조절할 수 있습니다. 후보 행에서 이름·거리·1인 가격을 비교하고 바로 ‘상세’ 또는 ‘추가’를 누를 수 있습니다. 상세 조회는 Choice 상태를 바꾸지 않습니다. 가운데 영역은 남은 높이에 고정하고 footer 높이는 76px로 유지합니다. 메뉴 펼침·접힘과 긴 내용은 우측 내부 스크롤로 처리해 지도 크기를 바꾸지 않습니다.
- 후보·코스 장소의 상세 버튼 또는 목록 더블클릭으로 지도 상세창을 엽니다. 두 지도의 장소 마커도 상세창과 연결됩니다. 후보 마커 선택은 오른쪽 후보 선택과 동기화되며 상세 조회만으로 코스에 추가되지 않습니다. 상세창에는 현재 데이터의 분류·가격·평점과 카카오맵 링크를 표시하고, 제공되지 않은 주소·영업시간·사진은 생성하지 않습니다.
- 장소 가격은 1인 기준으로 유지하고 예상 총액은 가격 합계 × 인원으로 계산합니다. 가격·평점은 DB 참고 정보, 거리와 점선은 직선 기준이며 실제 이동 경로·영업 여부·실시간 가격은 확인하지 않습니다.

## DB 준비

### 1. 사용할 DB 선택

- Aiven 등에서 이미 생성된 DB가 있으면 해당 DB를 사용합니다. 예: defaultdb.
- 로컬에서 새 DB가 필요하면 생성 권한이 있는 계정으로 [01_create_database.sql](data/sql/01_create_database.sql)을 실행할 수 있습니다. 이 스크립트는 university_project라는 DB를 만드는 선택적 초기화 도구입니다.
- DBeaver 등의 SQL 편집기에서 **앱과 같은 서버 및 DB를 선택한 뒤** [02_create_tables.sql](data/sql/02_create_tables.sql)을 실행합니다.

기본 테이블은 members, categories, data_records입니다. 테이블 생성 스크립트는 DB를 임의로 전환하지 않습니다.

### 2. 접속 설정

[db.properties.example](src/main/resources/db.properties.example)을 같은 폴더의 db.properties로 복사하고 실제 접속 정보를 입력합니다.

~~~properties
db.url=jdbc:mysql://YOUR_HOST:YOUR_PORT/YOUR_DATABASE
db.user=YOUR_USER
db.password=YOUR_PASSWORD
~~~

호스트·포트·DB 이름과 SSL 관련 옵션은 서버의 연결 설정에 맞춥니다. Aiven을 사용하면 로컬 예제 주소를 그대로 사용하지 않습니다.

- 세 항목 모두 필요하며 db.url에는 대상 DB 이름까지 포함합니다.
- URL이 없으면 localhost로 대신 연결하지 않고 설정 오류를 표시합니다.
- 비어 있지 않은 환경변수 DB_URL, DB_USER, DB_PASSWORD는 각각 파일 설정보다 우선합니다.
- 실제 db.properties는 Git 제외 대상입니다. 접속 비밀번호를 커밋하지 않습니다.

앱 시작 시 회원 저장소는 필요에 따라 members.password_hash를 확장하고 app_admins 테이블을 준비합니다. 접속 계정에는 해당 작업에 필요한 ALTER·CREATE 및 기능에 필요한 조회·변경 권한이 있어야 합니다. [06_membership.sql](data/sql/06_membership.sql)은 수동 준비용입니다.

## 회원가입·로그인 동작

- 회원가입 버튼을 누르면 첫 입력 단계로 바로 이동합니다.
- 이메일 → 비밀번호 → 확인 → 이름 → 전화번호 순서로 다음 버튼 또는 Enter를 사용합니다.
- 전화번호는 선택이며 이메일 중복 가입은 거부합니다.
- 비밀번호는 8~128자이며 PBKDF2 SHA-256, 600,000회, 개별 salt로 해시해 DB에 저장합니다.
- 로그인·회원가입·비밀번호 확인 입력란 오른쪽의 눈 아이콘으로 비밀번호 보기·숨김을 전환합니다. 입력을 비우거나 해당 화면이 숨겨지면 다시 마스킹하며 입력값·커서·Enter 동작은 유지합니다.
- 일반 회원은 가입 이메일로 로그인합니다. 비활성 계정은 로그인할 수 없습니다.
- 로그인 성공 후 UserSession에 회원 ID·이름을 담아 JavaFX 조건 입력 화면에 전달합니다.
- 로그인 성공 후 같은 창을 약 240ms 동안 지도 화면 크기로 확장하고, 지도·조건 화면을 260ms 페이드·짧은 슬라이드로 표시합니다. 인증이나 DB 조회 흐름은 변경하지 않습니다.
- DB 작업은 화면 스레드 밖에서 실행하며 회원 저장소의 연결은 HikariCP 풀에서 재사용합니다.

로그인 화면의 **아이디 저장**을 체크하고 로그인에 성공하면 아이디 하나를 .local/input-history.properties에 보관합니다. 다음 실행 시 자동 입력되며, 체크를 해제하면 저장 기록을 지웁니다.

비밀번호와 회원가입 이름·전화번호를 입력 추천용으로 저장하지 않습니다. 이전 버전의 이름·전화번호 추천 기록도 파일을 읽을 때 정리합니다.

## 장소 데이터 적재

[data/places/current/integrated_places.csv](data/places/current/integrated_places.csv)는 원본 데이터 파일입니다.

| category | 분류 | 건수 |
|---|---|---:|

| CAFE | 카페 | 2,447 |
| CULTURE | 문화 | 318 |

원본 필드는 id, name, category, lat, lon, price, rating입니다. 도로명 주소는 포함되어 있지 않습니다. DB의 data_payload에는 JSON으로 저장되며 호환용 businessName도 포함됩니다.

2026-11-09 점검 기준 CSV에는 이름·위도·경도가 같은 중복 묶음이 **188개** 있으며, 그중 **82개 묶음은 가격도 다릅니다**. 추천 시 중복을 제거하지만 CSV·DB 원본 자체를 정리한 것은 아닙니다. 가격·평점의 원출처는 확인되지 않았으며 목업으로 확정한 것도 아닙니다. 대표 메뉴·1인 가격 기준·출처·확인일을 검증하고 무료와 가격 미확인을 구분하는 작업이 남아 있습니다.

### Java 적재 프로그램

기본 테이블과 접속 설정을 준비한 다음, IntelliJ에서 **kr.ac.university.localdb.ReplaceIntegratedData.main()**을 실행합니다. Working directory는 프로젝트 루트로 지정합니다.

현재 프로그램은 CSV를 직접 해석하지 않고 [05_replace_integrated_data.sql](data/sql/05_replace_integrated_data.sql)을 읽습니다. CSV만 변경해도 적재 내용이 자동으로 바뀌지는 않습니다.

처리 순서:

1. 접속 설정의 DB에 연결합니다. SQL에 예전 USE 구문이 있어도 Java 적재에서는 건너뜁니다.
2. 기존 data_records, categories를 타임스탬프가 붙은 백업 테이블에 복사합니다.
3. 이전 카페·예제·통합 데이터 등 스크립트가 지정한 출처의 행을 교체합니다. 회원과 다른 출처의 장소 행은 유지합니다.
4. 장소 INSERT를 최대 250건씩 묶어 전송하고 커밋 전 진행 상황을 출력합니다.
5. 통합 장소 6,139건과 회원 수 유지를 확인한 뒤 커밋합니다. 교체 도중 오류가 발생하면 해당 트랜잭션을 롤백합니다.

성공 시 **장소 적재 커밋 완료**와 **SUCCESS: integrated dataset replaced**가 출력됩니다. 진행 건수 출력만으로 최종 저장이 끝난 것은 아닙니다.

백업은 CREATE TABLE ... LIKE로 기본 키·인덱스를 유지하고 데이터를 복사합니다. 외래 키는 복제하지 않습니다. 백업 생성은 교체 트랜잭션 밖에서 수행하므로 실패하거나 반복 실행한 경우에도 백업이 남을 수 있습니다.

SQL 파일을 DBeaver에서 직접 실행할 수도 있지만 Java 프로그램의 자동 백업·250건 묶음 처리·회원 수 검증은 적용되지 않습니다. 클라우드 적재에는 Java 프로그램을 기준으로 사용합니다.

## TMAP 보행자 경로 안내

카카오 지도 위에는 TMAP 보행자 API가 반환한 실제 도보 경로만 파란 실선으로 표시합니다. 장소 사이를 잇던 직선 연결선은 제외했습니다. 조회 전·실패 시에는 경로 선을 그리지 않고 상태를 안내합니다. 장소 마커·검색·반경 원은 그대로 사용합니다.

1. 메인 화면에서 출발 위치와 코스를 정한 뒤 **도보 경로**를 누릅니다.
2. 편집 화면에서는 하단 **도보 경로**를 누르면 바로 계산합니다. 현재 코스와 선택한 추천 후보까지 방문 순서대로 조회합니다.
3. 지도 아래에 실제 도보 거리·예상 이동 시간·구간 수를 표시합니다. **구간별 도보 안내 보기**를 펼치면 횡단보도·회전 등 API가 제공한 안내 문구를 확인할 수 있습니다.
4. 출발지·방문 장소·순서·선택 후보가 바뀌면 이전 도보 표시와 진행 중 요청을 무효화합니다. 새 코스는 버튼으로 다시 조회합니다. 반경이나 인원만 바뀌면 같은 경로를 유지합니다.

사용자는 메인·편집 화면의 별도 **도보 설정**에서 추천·대로 우선·최단·계단 제외를 선택합니다. 기존 앱의 코랄 색상과 카드 UI를 사용하며, 일반 사용자 화면에는 appKey 입력란이 없습니다. 경로가 선택된 상태에서 방식을 적용하면 새 조건으로 다시 조회합니다.

앱 제공자의 **SK open API TMAP appKey**를 모든 사용자가 공통으로 사용합니다. 개발·빌드용 키는 Git 제외 대상 `.local/tmap.properties` 또는 환경변수 `TMAP_APP_KEY`에서 준비합니다.

~~~properties
tmap.app.key=본인_TMAP_appKey
tmap.search.option=0
~~~

공통 접속 키가 있으면 `TeamApiKeys`가 서버에서 TMAP 키를 받아 메모리에 보관합니다. 공통 설정이 없는 경우에만 기존 환경변수·로컬 파일을 읽습니다. `prepareTmapServiceConfig`는 빈 설정만 만들어 예전에 포함되던 키를 새 빌드에서 제거합니다. 키는 Java HTTP `appKey` 헤더로 사용하며 지도 HTML·JavaScript에는 전달하지 않습니다.

사용자의 탐색 방식은 `.local/tmap-route.properties`에 별도로 저장하고 공통 키 파일을 변경하지 않습니다. 탐색 방식 코드는 추천(0), 추천·대로 우선(4), 최단(10), 최단·계단 제외(30)입니다. 개발용 설정 예제는 `src/main/resources/tmap.properties.example`에 있습니다.

- 요청은 `POST https://apis.openapi.sk.com/tmap/routes/pedestrian?version=1`이고 요청·응답 좌표계는 모두 `WGS84GEO`입니다. 요청 X는 경도, Y는 위도입니다. 거리 단위는 미터, API 시간 단위는 초이며 화면은 분 단위로 올림 표시합니다.
- 출발지 → 1번 장소 → 2번 장소 순으로 **구간마다 한 번씩** 요청합니다. 동일 구간·키·탐색 방식의 성공 결과는 최대 64건을 5분간 메모리에 재사용합니다. 경로 조회 버튼 또는 탐색 방식 적용으로 조회합니다.
- HTTP 요청은 백그라운드에서 실행하며 연결 제한 5초·응답 제한 20초를 둡니다. 인증·권한 오류, 요청 한도 초과, 응답 누락, 연결 실패를 구분해 안내합니다. 실패한 조회를 성공한 도보 거리로 표시하지 않습니다.
- 기존 추천·반경 검사는 직선거리 기준으로 유지됩니다. TMAP 도보 거리·예상 시간은 별도 안내입니다. 지도에 경로를 표시하는 기능이며 GPS 추적이나 음성 내비게이션은 제공하지 않습니다.
- 사양 출처: [보행자 경로안내](https://tmap-skopenapi.readme.io/reference/보행자-경로안내), [경로안내 샘플예제](https://tmap-skopenapi.readme.io/reference/경로안내-샘플예제).

기본 테스트는 모의 HTTP 응답과 JavaFX 지도 대역으로 요청 좌표·인증 헤더·경로 해석·오류·캐시·오래된 응답 무시·카카오 지도 위 경로 표시를 확인합니다. 실제 키로 카카오 지도와 TMAP API를 함께 확인하려면 기존 앱과 수동 지도 서버를 닫아 8080 포트를 비운 뒤 데스크톱에서 다음 선택 검사를 실행합니다. 실제 TMAP 호출이 발생합니다.

~~~powershell
.\gradlew.bat tmapLiveTest
~~~

검사에 성공하면 `build/ui-preview/tmap-walking-live.png`에 실제 지도와 도보 경로 미리보기를 저장합니다.

### 로그인 후 화면 전환 로딩

일반 회원 인증에 성공하면 다음 JavaFX 화면을 만드는 동안 **앱을 실행중입니다..** 메시지와 진행 표시를 보여 줍니다. 준비가 끝나면 로딩창을 닫고 조건 입력 화면으로 전환합니다. 화면을 열지 못한 경우에도 로딩창을 닫아 로그인 창을 다시 사용할 수 있게 하고 오류를 안내합니다. 인증·회원 저장·관리자 로그인 처리 자체는 변경하지 않습니다.

## 브랜치 운영과 로컬 파일

- master: 검증된 팀 공통 코드
- feature/*: 지도 연결·장소 수 조회·추천·저장 등 기능별 작업
- 기능 완료 후 빌드·테스트·수동 동작을 확인하고 PR로 master에 병합합니다.
- 새 기능은 최신 master에서 시작합니다. 기존 통합 브랜치는 이전 작업 이력으로 남아 있습니다.

개인 DB 설정 `db.properties`, 카카오 키 설정 `src/main/resources/map/kakao-config.js`, 아이디 기록 `.local/`, 개인 IDE 설정 및 `.codex/config.toml`은 Git에서 제외합니다. 공유할 설정 형식은 `db.properties.example`과 `kakao-config.example.js`에서 관리합니다. **Git 제외와 배포 파일 제외는 별개**이며, 현재 로컬 리소스가 JAR에 포함되는 문제는 위 알려진 문제에 기록되어 있습니다.
