# 새 장소 데이터의 프로그램 통합 (2026-11-15)

## 객체의 역할

| 객체 | 책임 |
| --- | --- |
| Place | 안정적인 공공 ID와 장소 동일성 판단 |
| PlaceDetails | 속성의 가능·불가능·미확인 해석과 확인된 선택 태그 제공 |
| PriceEstimate / SourceEvidence | 가격 단위·추정 근거·원본 기준일·검토/계산일 보존 |
| PlacePresenter | 모델을 사용자용 가격 문구·배지·간략 설명으로 구성 |
| PlaceMapPayload | 모델과 표시 결과를 지도 전달용 JSON으로 변환 |
| Controller | 사용자의 선택·검색·추가·화면 갱신 이벤트 처리 |
| PlaceSource 구현체 | 운영 DB 또는 공공/시연 목록 로딩 |

도메인 모델은 불변 record이며 화면이나 네트워크 호출에 의존하지 않는다. PlacePresenter는 표시 전용 객체이고 PlaceMapPayload는 경계 어댑터다. 같은 PlacePresenter를 후보 목록과 지도에서 합성하여 사용한다. 현재 교체할 구현이 없는 객체에는 별도의 인터페이스를 추가하지 않았다. 데이터 출처 교체는 기존 PlaceSource를 사용한다.

## 반영된 동작

- 후보 목록: 가격의 참고/추정 여부와 핵심 특징 최대 두 개를 표시한다. 더 자세한 근거는 툴팁으로 제공한다.
- 지도 상세: Java에서 준비한 가격 문구·특징 배지·주소·세부 분류·연락처·간략 설명을 표시한다. 긴 출처 URL이나 계산 표본 수는 기본 화면에 나열하지 않는다.
- 교통 특징: 배지의 설명에 역사/정류장 좌표 기준 직선거리라는 근거와 자료 기준일·계산일을 구분해 남긴다. 도보 시간으로 표현하지 않는다.
- 상태 해석: 태그 목록에 직접 들어 있지 않아도 typed 속성이 AVAILABLE이면 배지와 특징 조건에 나타난다. UNAVAILABLE/UNKNOWN은 가능 배지로 표시하지 않는다.
- 특징 조건: 확인된 정보가 있는 항목만 선택 목록에 나타난다. 선택하면 불가·미확인 장소는 제외된다는 안내를 제공한다.
- 지원 시설: 예약·단체·포장·채식·야외 좌석·반려견·주차·어린이·휠체어 출입을 표현할 수 있다. 실제 운영 자료에 없는 시설 값을 채워 넣지 않았다.
- 동일성: 운영 DB/시연/저장본의 화면 ID가 달라도 공공 ID가 같으면 이미 선택한 장소로 처리한다. 공공 ID가 서로 다르면 이름과 좌표가 같아도 자동 병합하지 않는다.
- 제보: 정정 대상의 키에도 같은 Place의 안정적인 ID 판단을 사용한다.
- 목록 선택: 운영 DB 목록을 '운영 장소 목록'으로 표시하고 가격 상태 집계는 공통 표시 객체에서 구성한다.
- 좁은 지도: 상세 카드 최대 높이를 조정하여 420px 폭에서도 추가 버튼이 카드 안에 보이도록 했다.

## 저장과 조회 경계

presentation은 지도 전달용 JSON에만 붙는다. 영구 Place JSON이나 저장 코스에 표시 문구를 넣지 않는다. 운영 DB에 이미 적재한 127곳의 내용 지문은 그대로이며 이번 UI 통합으로 재적재하지 않았다.

Google 실제 상세 값은 현재 영구 자료에 포함되지 않는다. 이번 변경은 확보한 공공자료의 표시와, 근거가 확보된 시설 속성을 표현하는 경로를 연결했다. 이전 실험의 반환 건수를 개별 가게의 시설값으로 변환하지 않았다. 실시간 Google 조회와 공식 UI Kit 표시는 별도 제공자 어댑터 단계다.

## 검증

전체 테스트 249개 통과, 실패·오류·건너뜀 0. JAR 빌드와 적재 미리보기 통과. 미리보기 지문은 기존 운영 적재와 동일한 `404ad64d98e7d697cd63972728148508d64e4b7f29738b729dd861ff71951386`이다.

추가 검증은 다음을 포함한다.

- 공공자료 127곳의 실제 가격 근거·교통 특징과 기준일을 표시 모델로 변환.
- 확인·불가·미확인 시설의 배지/필터 일치.
- 표시 JSON과 영구 모델의 분리, 기존 JSON round-trip.
- 공공 ID가 같고 장소명/좌표가 정정된 저장본의 중복 제외.
- WebView에서 실제 자료 카드 렌더링, 850/420px 폭의 가로 넘침과 추가 버튼 위치.
- JavaFX 조건 폼에서 typed 예약 속성이 선택 항목과 검색 결과에 반영되는 흐름.

시각 검증 이미지: `build/ui-preview/public-data-detail-850.png`, `build/ui-preview/public-data-detail-420.png`. 지도 SDK는 기존 테스트 fixture를 사용했으며 Google API 추가 호출이나 운영 DB 쓰기는 수행하지 않았다.

## 확정 장소 핀과 경로 상호작용

빨간 확정 장소 핀의 클릭은 장소 상세정보를 연다. 이전 도착 경로를 우선 선택하던 분기를 제거했다. 경로선과 구간 번호의 hover·클릭은 기존 경로 설명을 유지한다.

장소 핀 hover는 방문 순서·장소명·가격·핵심 특징 최대 두 개와 클릭 안내를 보여준다. 선택 상태·경로 선택·지도 중심을 바꾸지 않는다. 기존 Java 표시 모델에서 만든 문구를 사용한다.

미리보기 객체는 지도당 오버레이 하나를 재사용하며 표시와 숨김 수명을 관리한다. 화면 가장자리에서는 위치를 보정하고 포인터 이벤트를 받지 않아 핀 클릭을 가리지 않는다. 핀 이탈·상세정보 열기·목록 교체·초기화 시 정리하고, 제거된 핀에서 늦게 온 hover는 무시한다. 텍스트는 DOM textContent로 렌더링한다.

후속 전체 검증: 테스트 251개 통과, 실패·오류·건너뜀 0. 경로가 있는 상태의 장소 클릭, 경로 클릭 유지, hover의 비선택 동작, 핀 이탈/교체/초기화 수명과 HTML 문자열의 텍스트 처리를 검증했다. `build/ui-preview/place-pin-hover.png`에서 hover UI를 시각 검토했다. 지도는 기존 테스트 fixture를 사용했다.
