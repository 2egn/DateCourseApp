# 장소 표본 확대 · 2026-11-16

기존 127곳을 유지하면서 259곳을 추가해 **386곳**으로 확대했다. 서면 중심 2km 범위는 유지한다.
식사 240곳·카페 120곳·문화 26곳이다. 문화 2개 추가 공공 기록은 같은 이름이지만 지번과 좌표가 달라 구분됐다.

## 생성과 신뢰도

- `data/places/demo/selection-policy.json`에서 중심·반경·업종별 상한·우선 표본 수를 조절한다. 기존 장소를 제외하거나 상한이 기존 수보다 작아지면 조용히 삭제하지 않고 실패한다.
- 기존 장소의 ID·recordId·좌표·가격은 baseline manifest와 대조했다. 같은 자료를 다시 생성해도 JSON 바이트가 같다.
- 기존 공공 원본·교통·지정 자료만 재사용했다. 생성일·계산일은 갱신하되 원본 기준일·출처와 외부 연결 검토 상태는 보존한다. 전체 장소의 현재 영업이나 Google 동일성을 새로 검증했다는 뜻은 아니다.
- 가격은 유사 유형 추정 265곳·공공 기준값 2곳·미확인 119곳이다. 새로 확인하지 않은 요리·시설의 가격은 채우지 않았다.
- 착한가격 40곳·모범음식점 3곳·역 가까움 368곳·정류장 가까움 385곳·무료입장 1곳이다. 근접도는 실제 도보가 아닌 직선거리다.

## 생성 명령

```powershell
python tools/build_public_demo.py
python tools/collect_busan_appeal_data.py --offline
.\gradlew.bat previewPlaceImport
```

첫 도구는 LF로 출력한다. 두 번째는 원본 파일 체크섬을 검증하고 네트워크 없이 속성을 재계산한다. 원본 파일 갱신은 별도의 수집 작업이다.
원본과 속성 팩의 지문을 함께 갱신하므로 한 파일만 교체하지 않는다.

## 후보 모의 검사

출발지 중심 2km, 다음 장소 반경 2km, 1인 상한 2만원 기준이다. 화면 표시 수는 최대 30곳으로 유지한다.

| 활동 | 가격 근거가 있는 후보 | 미확인 포함 |
|---|---:|---:|
| 식사 | 145 | 240 |
| 카페 | 120 | 120 |
| 문화 | 2 | 26 |

문화 장소가 많아져도 가격 미확인 24곳을 무료로 계산하지 않는다. 다양한 문화 후보를 보려면 가격 미확인 포함 조건을 사용한다.

## 검증

Java 325개·Python 63개, JAR와 오프라인 적재 미리보기가 통과했다. 신규 검사는 기존 127곳 보존,
생성 반복의 동일성, 업종 상한·중복·검토 제외, 오프라인 원본 재사용과 가격 미확인 분리를 포함한다.

## 운영 적재

전체 버전 적재로 진행하며 기존 번호와 저장 코스·이미지·제보·정정 자료를 전후 비교한다.
같은 버전 재적재는 신규·변경·비활성 없이 유지되는지 확인한다. 실제 MySQL 적용 결과는 신규 259·갱신 127·재활성 0·비활성 0·유지 0이며 활성/정정 적용 조회가 모두 386곳이었다.
기존 127개 record_id가 유지됐고 저장 코스·장소 스냅샷·이미지·제보·정정 테이블의 전후 내용 지문도 같았다.
같은 버전 재적재는 신규/갱신/재활성/비활성 0, 유지 386이었다. 갱신 127은 속성 계산일을 새 버전으로 반영한 것으로 기존 가격·좌표를 새 값으로 추정해 덮어쓴 것이 아니다.

실행 중인 앱은 장소 목록이 메모리에 남아 있을 수 있으므로 재시작해 새 카탈로그를 읽는다.
원격 Git 브랜치와 문서 사이트 배포는 이 적재와 별도 작업이다.
