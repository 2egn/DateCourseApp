## 추천 후보의 중복 계산 정리

`NextPlaceService.matching()`은 전체 범위에서 끝낸 장소 유효성·공공 ID 우선 중복 선택을 재사용한다. 첫 장소는 출발지 거리를 그대로 쓰고, 이후 장소는 직전 장소 거리만 다시 계산한다. 전체·구간 반경의 교집합, 가격·특징 필터, 거리·ID 순서와 표시 수는 유지한다.

현재 2,040곳 기준본으로 출발지 세 곳 × 활동 세 종류 × 구간 반경 두 종류 × 확정 장소 유무를 대조한 36개 조건에서 전체 후보 레코드·거리·순서가 이전 결과와 일치했다. 이 비교는 운영 DB 없이 파일로 수행했다.

로컬 JDK 21·최대 힙 256MB, 준비 실행 1회 뒤 1,260번 매칭을 다섯 차례 측정한 중앙값은 200.46ms에서 159.78ms였다. 이 수치는 해당 입력의 로컬 계산 측정이며 앱 전체 반응 속도·DB·API 성능 수치가 아니다. 기존 결과 보존과 불필요한 검사 제거를 변경 근거로 삼는다.

추가 입력 경계 확인: 원래 버튼이 비활성화되어 DOM 포커스 이동이 거부되면 보이는 지도·이미지로 복귀한다. 저장 장소 행의 우클릭·가운데 클릭은 지도 전환으로 처리하지 않는다.

편집 내 코스의 더블클릭은 채워진 장소 셀의 기본 버튼에만 연결했다. 빈 목록 영역과 보조 버튼의 더블클릭은 이전 선택의 상세를 열지 않으며, Enter 상세는 유지한다.

저장 코스 전환·초기화 때 이전 화면 전용 미리보기 변환 Future를 취소하고 참조를 해제한다. UserContext의 공유 BLOB 조회는 취소하지 않아 재선택·다른 화면에서 재사용할 수 있다. 이미 실행 중인 이미지 디코딩을 강제 중단하지 않으며, 이전 결과 반영은 기존 요청 번호 검사로 차단한다.

경로 공급사가 메시지 없는 IOException·입력 오류를 반환해도 null·빈 문자열을 화면에 전파하지 않고 이동수단별 실패 안내와 재조회 버튼을 유지한다.
