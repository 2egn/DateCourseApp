# 지도 움직임 비교 시안

JavaFX에서 실제 Kakao 지도를 두 개 띄워 같은 출발지와 반경을 비교한다. DB 접속과 운영 화면의 카메라 코드는 변경하지 않는다.

## 실행

```powershell
.\gradlew.bat runCameraMotionDemo
```

기존 팀 Kakao JavaScript 키 설정과 허용 도메인 `http://localhost:8080`을 사용한다. 같은 포트의 운영 앱을 먼저 종료해야 한다. 별도 API 키나 DB는 필요 없다.

## 비교할 내용

- **왼쪽 기존 방식**: 출발지 선택은 `setCenter`, 반경 변경은 매번 `setBounds`.
- **오른쪽 개선 시안**: 가까운 이동은 배율을 유지하고 `panTo`, 중심과 배율 변경은 SDK `jump` 사용. 지원하지 않는 SDK에는 기본 API 조합으로 대응한다.
- 반경 드래그 중 원은 바로 갱신하되 화면을 벗어날 때만 축소한다. 놓으면 최종 반경에 한 번 맞춘다.
- 이동 중 요청은 마지막 것 하나만 보관한다. 직접 지도 드래그/휠 조작은 대기 요청과 자동 3곳 선택을 취소한다.
- 동작 줄이기 선택 및 OS의 reduced-motion 설정은 개선 시안에 반영한다.

`가까운 곳 비교`를 여러 번 누르거나, 지도 클릭, 반경 슬라이더, `빠른 3곳 선택`을 사용한다. 좌우 지도는 직접 드래그할 수 있다. 직접 조작 시점의 카메라는 서로 독립적이므로 `처음으로`를 누르면 같은 상태에서 비교를 재개할 수 있다.

## 구조

- `CameraMotionPolicy`: 화면 기준 거리, 범위 초과 비율과 사용자 의도로 이동 방식을 결정하는 Java 정책 객체.
- `CameraMotionDemoApp`: JavaFX 비교 화면과 같은 입력의 양쪽 전달.
- `camera-motion-demo.js`: SDK 좌표 측정과 명령 실행, idle 기반 마지막 요청 처리.

장소별 예외나 일정 시간 뒤 강제 재중심 맞춤은 두지 않는다. `.85` 화면 길이의 근거리 기준, 범위 초과 4% 여유와 220~600ms 목표 시간은 시안 기본값이며 실제 사용감 평가 후 조정한다. `panTo`의 실제 시간은 SDK가 결정한다.

## 검증

```powershell
.\gradlew.bat test
.\gradlew.bat cameraMotionLiveTest
```

첫 명령은 오프라인 회귀 테스트, 둘째는 명시적으로 실제 Kakao 지도를 호출하는 검사다. 두 지도 준비, 가까운 이동, 반경 변경, 빠른 재선택의 최종 좌표·반경·대기 해제와 JavaScript 오류를 확인한다. 실제 화면 캡처는 `build/ui-preview/camera-motion-demo.png`에 생성한다.

장거리 이동의 타일 공급과 애니메이션 연속성은 SDK와 네트워크 영향을 받는다. 모든 거리에서 같은 부드러움을 보장하는 자체 카메라 엔진은 이번 범위에 포함하지 않는다. 운영 통합 전에는 상세 카드 자동 이동과 범위 맞춤도 같은 정책 경계로 묶어야 한다.
