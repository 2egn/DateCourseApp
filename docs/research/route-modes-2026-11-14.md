# 자동차·대중교통 경로 확장 검토

확인일: 2026-11-14. 공식 공개 문서 검토이며 실제 계정의 권한·상품 가입·남은 무료량은 확인하지 않았다. 이번 UI 변경에서 새 경로 API를 호출하거나 유료 상품을 활성화하지 않았다. 현재 실제 계산은 기존 TMAP 도보 경로다.

## 선택지

| 수단 | 검토한 서비스 | 공식 안내의 무료 범위·조건 | 판단 |
|---|---|---|---|
| 자동차 | TMAP 자동차 경로 | 경로안내 분류 일 1,000건 안내. 현재 앱키의 상품 권한은 별도 확인 | 기존 Java HTTP 경로와 유사해 확장 후보 |
| 자동차 | 카카오모빌리티 자동차 길찾기 | 카카오 쿼터 문서에 일 10,000건 안내. REST API 키 필요 | 현재 카카오 지도 위에 자동차 경로를 붙이는 후보 |
| 대중교통 | TMAP 대중교통 | 무료체험 경로·요약 각각 일 10건 안내 | 여러 구간·반복 시연에는 적은 편 |
| 대중교통 | 카카오맵 REST 경로 조회 | 일 1,000건 안내. 카카오맵 무료 쿼터는 개발자 계정에서 첫 번째로 활성화한 앱에만 제공 | TMAP 이외에 우선 확인할 대안 |
| 자동차·대중교통 | 카카오맵 외부 길찾기 링크 | 공식 링크 형식 제공. 앱 내부에서 API 응답을 계산·표시하는 방식과 다름 | 제출 일정이 촉박할 때 가장 작은 연결 범위 |

무료 제공량은 호출할 수 있는 전체 조건을 보장하지 않는다. 앱별 권한·상품 설정·쿼터 공유·초과 시 정책을 적용 전에 확인한다. JavaScript 지도 키와 REST API 키는 역할이 다르므로 서로 대체하지 않는다.

## 권장 순서

**이번에는 도보 표시와 코스 흐름을 안정화한다.** 자동차·대중교통을 동시에 넣으면 경로 정보뿐 아니라 요금·환승·주차·도착 후 도보 구간까지 설계 범위가 커진다.

1. 일정이 부족하면 구간별 외부 카카오맵 길찾기 연결을 먼저 고려한다. 외부 화면 이동임을 표시한다.
2. 앱 내부 표시가 필요하면 자동차 한 가지를 먼저 검증한다. 현재 TMAP 상품 권한과 카카오 REST 설정 중 준비가 적은 쪽을 선택한다.
3. 대중교통은 카카오 REST의 실제 앱 적용 조건을 먼저 확인한다. TMAP 무료체험 일 10건만으로 충분한지도 비교한다.

카카오 대중교통 REST 문서에는 소요 시간·거리·요금·환승과 단계별 좌표가 있다. 따라서 기술적으로 표시할 재료는 있지만, 현재 앱 계정에서 실제 응답을 받았다는 뜻은 아니다.

## 구현하게 되면 달라질 부분

- 현재 `WalkingRouteService`는 도보만 계산한다. 자동차 응답을 그대로 ‘도보’라고 표시하지 않는다. 수단을 구분하는 모델과 계산 담당자를 둔다.
- 번호·색·hover·구간 선택 UI는 재사용할 수 있다. 요금·환승은 해당 수단에 있을 때만 표시한다.
- 코스 장소 비용과 교통비를 구분한다. 자동차 예상 시간에 주차·매장 입장까지 포함됐다고 가정하지 않는다.
- 구간 5개를 각자 요청하면 API 호출도 5번이다. 전체 코스를 다시 계산하는 횟수까지 고려한다.
- TMAP 결과는 공식 안내의 24시간 사용 제한을 고려하고, 경로 응답을 장소 DB에 영구 저장하지 않는다.
