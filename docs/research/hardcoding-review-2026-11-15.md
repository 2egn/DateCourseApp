# 하드코딩 검토 — 2026-11-15

값을 전부 설정 파일로 옮기는 방식은 사용하지 않았다. 같은 정책이 여러 곳에서
서로 달라질 위험이 있는지, 실행 환경마다 바뀌어야 하는지, 단순한 화면 치수인지로 구분했다.

## 이번에 정리한 중복

- 지도 캡처 크기와 PNG 합성 크기는 CoursePreviewImage의 공통 규격을 사용한다.
  PlannerMap과 별도 재생성 창이 같은 지도 크기를 참조한다.
- 저장/재생성의 PNG 용량 제한은 MAX_PNG_BYTES 하나를 사용한다.
- 모델의 허용 후보 수와 화면 선택지는 NextPlaceCondition.DISPLAY_LIMITS를 공유한다.
  5는 최대 수가 아니라 기본 수이므로 NextPlaceService의 상수 이름도 DEFAULT_CANDIDATES로 고쳤다.
- 캡처 대기 시간은 PlannerMap의 CAPTURE_TIMEOUT으로 의미를 드러냈다.
- 별도 미리보기 창의 초기 표시 반경은 임의 500m 대신 해당 코스 반경을 사용한다.

모두 기존 클래스의 상수/값 재사용이며 새 설정 프레임워크나 큰 추상화 계층은 추가하지 않았다.

## 현재 유지한 값

- 인원 1~20명, 전체/구간 반경 200~2000m: 현재 기획과 DB 제약에 연결된 정책이다.
  여러 검증 계층에 반복돼 있으므로 기획이 바뀔 때 모델·폼·DB 제약을 함께 바꿔야 한다.
  이번에는 범위 자체나 SQL 제약을 변경하지 않았다.
- API 주소/응답 코드, 거리 계산의 물리 상수: 외부 프로토콜·계산 규칙이다.
- 시연 장소와 부산 시작 좌표: 시연 저장소 안의 데이터다. 일반 사용자 위치와 구분돼 있다.
- 여백·글자 크기·모서리: 공통 스타일에서 역할별로 유지한다. 모든 픽셀을 별도 설정으로 추출하지 않는다.
- 한글 안내 문구: 현재 단일 언어 앱의 일반적인 UI 리터럴이다.

## 실행 환경과 함께 검토할 항목

- 지도 서버 8080 포트는 지도 키의 허용 도메인과 연결된다. 임의 변경 대신 단일 실행/배포 설정과 함께 결정한다.
- 초기 관리자 계정 시드가 코드에 있다. 공개 배포 시 초기 관리자 설정 절차를 별도로 정리해야 한다.
  검토 문서와 로그에 계정 해시·키·접속 값을 복사하지 않았다.
- 공통 API 키/DB 접속 정보는 기존 런타임 설정 흐름을 사용한다. 이번 작업에서 실제 접속 값은 변경하지 않았다.

## 복잡도를 늘리지 않은 방법

기본 JavaFX 컨트롤, 기존 CSS/UiTheme, 작은 DialogTheme 헬퍼, 기존 모델의 상수를 사용했다.
사용자/개발자 정보 구분도 화면 문구와 안전한 진단 로그의 역할 분리로 처리한다.
범용 UI 프레임워크, 동적 정책 엔진, 자동 설정 탐색 계층은 추가하지 않았다.
