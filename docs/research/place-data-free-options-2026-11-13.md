# Place 데이터 개선에 쓸 무료 수단 검토

검토일: 2026-11-13 (한국 시간)  
대상: DateCourseApp, 부산 서면·전포 시연용 별도 데이터셋  
기준: 과제의 정상 시연, 추가 지출 0원, 기존 원본·DB를 덮어쓰지 않기

## 결론

**기본 데이터셋은 국내 공공자료로 만들고, 가격은 기준이 확인된 메뉴·입장료로 범위를 계산하며, Google 정보는 원본 보강과 구분해서 다루는 방향을 추천한다.**

무료 호출과 결과의 영구 보관은 다른 조건이다. API를 무료로 호출할 수 있어도 응답을 CSV·DB에 쌓거나 다른 지도와 결합할 수 있다고 가정하지 않는다. 아래 평가는 공식 문서와 현재 로컬 자료를 확인한 결과이며, 인증키를 사용한 각 API의 실응답·서면 지역 실제 수록률까지 시험한 결과는 아니다.

이번 결과물은 검토 문서다. 기존 CSV·SQL·DB·앱 데이터 연결은 변경하지 않았다. 테스트 데이터셋 생성과 앱의 가격 범위 표시는 후속 구현이다.

## 1. 무료의 구분

| 구분 | 의미 | 해당 예 |
|---|---|---|
| 공개 파일·무료 공공 API | 자료 자체가 무료. API 키·신청·출처 표기 등은 자료별 확인 | 상가정보, 착한가격업소, 인허가, TourAPI |
| 무료 사용량이 있는 상용 API | 지정한 호출량 안에서 무료. 영구 보관 권한과 별개 | 카카오·네이버·TMAP·Geoapify·Google의 무료 구간 |
| 체험 크레딧 | 정해진 기간·금액 안에서만 사용 | 사용자가 시작한 Google Free Trial |
| 무료 오픈데이터·로컬 도구 | 파일 접근·로컬 처리에 별도 API 이용료가 없음. 라이선스·설치·처리량은 고려 | OSM, Overture, FSQ OS Places, OpenRefine, pyproj, Tesseract |

Google Free Trial은 일반적으로 90일·300달러 조건이며, 유료 계정으로 수동 전환하지 않은 Trial 계정은 기간·크레딧 소진 시 종료된다고 안내한다. 사용자가 말한 420,977원 잔액은 이 문서에서 계정에 접속해 확인한 값이 아니다. 실제 계정의 Trial/Paid 상태와 만료일을 따로 확인해야 한다. [Google 공식 안내](https://cloud.google.com/signup-faqs)

## 2. 기본 장소·영업 상태·가격에 우선 사용할 수단

| 수단 | 얻을 수 있는 정보 | 무료·보관 판단 | 이번 과제 우선도 |
|---|---|---|---|
| 소상공인시장진흥공단 상가정보 CSV | 상호, 지점, 업종, 주소, 좌표, 식별자 | 무료 파일. 공개 이용 조건을 지키며 기본 자료로 사용하기 좋음. 실시간 영업 보증은 아님 | 높음 |
| 일반음식점 인허가 API/파일 및 휴게음식점 자료 | 허가 상태, 사업장명, 주소, 영업·폐업 관련 기록 | 무료 공공자료. 업종별로 수집·매칭. 영업 상태는 자료 기준 시점의 행정 정보 | 높음 |
| 부산진구 일반음식점 현황 CSV | 시연 구역에 가까운 식당 기초정보 | 지역 한정 무료 보조 자료. 게시 기준일과 실제 열을 확인하고 사용 | 보통 |
| 행정안전부 착한가격업소 CSV | 상호·주소와 메뉴 1~4의 금액 | 무료 파일. 현재 프로젝트에 이미 부산 자료가 있음. 1인분·세트 구분은 별도 | 높음 |
| 부산시 착한가격업소 메뉴 API | 업소명, 품목명, 메뉴가격, 생성일시 | 무료 공공 API. 지정 업소 범위만 제공 | 높음 |
| 부산맛집정보 API | 주소·좌표·영업시간·대표메뉴·설명·이미지 | 무료. 설명은 풍부하나 표준 응답에 숫자 가격·방문자 리뷰 본문이 보장되는 것은 아님 | 높음 |
| 부산푸디투어 API | 음식 골목·관광 콘텐츠·장소 설명 | 무료. 골목 전체 콘텐츠를 개별 가게 한 곳으로 넣지 않도록 구분 | 보통 |
| 한국관광공사 TourAPI | 관광지·문화시설·음식점·행사·이미지·유형별 소개 | 무료. 내용별 채움 정도가 다르고 이미지 이용 조건도 구분 | 높음 |
| 박물관·미술관·도서관·공원 표준자료 | 시설 위치·운영 정보·일부 관람료 | 현재 원본에 이미 포함. 문화 활동 후보를 확보하는 기본 자료 | 높음 |

- [일반음식점 파일](https://www.data.go.kr/data/15045016/fileData.do), [부산진구 현황](https://www.data.go.kr/data/15025552/fileData.do).
- [착한가격업소 CSV](https://www.data.go.kr/data/3045247/fileData.do), [부산 메뉴 API](https://www.data.go.kr/data/15145474/openapi.do).
- [부산맛집정보](https://www.data.go.kr/data/15063472/openapi.do): 대표메뉴·연락처·주소·좌표·운영시간 열을 확인했다. 소개문에 리뷰를 언급하더라도 실제 표준 응답에 리뷰 본문 열이 있는지 실응답 검증이 필요하다.
- [부산푸디투어](https://www.data.go.kr/data/15063507/openapi.do), [TourAPI](https://www.data.go.kr/data/15101578/openapi.do).

부산맛집·착한가격·TourAPI의 가격은 모든 장소의 현재 결제 금액을 보장하는 자료가 아니다. 원문 기준일과 수집일을 따로 기록한다.

## 3. 검색·좌표 확인에 쓸 수단

| 수단 | 유용한 일 | 이번 판단 |
|---|---|---|
| 카카오 Local/현재 지도 검색 | 상호·지점·주소·좌표·상세 링크 대조 | 기존 연결을 활용. 검색 실패만으로 폐업 판정하지 않음. 응답의 영구 축적 허용은 별도 확인 |
| 네이버 지역 검색 | 다른 검색 결과로 상호·주소를 확인 | 일반 응답에 메뉴가격·별점·방문자 리뷰 본문은 없음. 한 번에 최대 5개라 개별 확인에 적합 |
| TMAP POI 통합·상세 검색 | 이름·주소·전화·좌표·분류 확인, 도보 서비스와 연계 | 현재 TMAP 키를 활용할 후보. 실제 상품 권한·무료 구간·보관 조건 확인 후 소량 사용 |
| 주소기반산업지원서비스 주소 API | 도로명·지번 주소를 통일하고 건물관리번호 등으로 매칭 | 무료. 주소 정규화에 적합. 같은 건물의 여러 가게까지 같은 업소로 합치면 안 됨 |
| VWorld 지오코더 | 주소의 좌표를 실시간으로 확인 | **현재 공개 안내에 응답을 별도 저장장치·DB에 저장할 수 없다고 명시. 영구 좌표 보강용으로 기본 채택하지 않음** |

공공데이터의 상단 이용허락 표시만 보지 않고 상세 설명과 원 제공기관 조건도 함께 확인한다. 좌표가 있는 건물과 해당 가게의 입구는 다른 개념이다.

## 5. Google Places와 리뷰

Google Places는 가격 수준·범위, 평점·리뷰 수·일부 리뷰를 조회할 수 있다. Place Details의 가격·평점 관련 Enterprise 등급과 리뷰를 포함하는 Enterprise + Atmosphere 등급은 현재 공식 요금표상 각각 월 1,000건 무료 구간이 있다. 요청 필드에 따라 등급이 결정되며, 같은 결제계정의 다른 사용량도 고려한다.

**크레딧이 있어도 Google 응답을 기존 CSV·DB에 영구 복사해 장소 데이터셋을 만드는 방식으로 바로 쓰지 않는다.** 공식 정책은 보관·추출·파생 활용을 제한한다. Place ID는 보관 예외이며, 지도 표시·로고·리뷰 작성자 표시 등은 별도 조건이다. 카카오맵과 함께 쓰는 실제 표시 방식은 구현 전에 확인해야 한다.

리뷰 본문은 최대 5개 수준이며 모든 가게에 평점·가격·리뷰가 있는 것은 아니다. Google 정보를 쓰더라도 원본 출처를 숨겨 자체 평점으로 저장하지 않는다.

- [필드와 등급](https://developers.google.com/maps/documentation/places/web-service/data-fields)
- [월 무료량·요금](https://developers.google.com/maps/billing-and-pricing/pricing)
- [리뷰 조회](https://developers.google.com/maps/documentation/places/web-service/place-details)
- [보관·표시 정책](https://developers.google.com/maps/documentation/places/web-service/policies)
- [실제 호출 제한과 예산 알림의 차이](https://developers.google.com/maps/billing-and-pricing/manage-costs)

리뷰를 무료로 확보하는 다른 방향은 앱 사용자가 실제로 작성한 자체 후기다. 외부 리뷰와 섞지 않고 별도로 표시한다. 과제용 가상 후기를 실제 고객 후기처럼 표시하지 않는다.

## 6. 무료 정제 도구도 활용

| 도구·방법 | 용도 | 한계 |
|---|---|---|
| OpenRefine | 상호 표기 차이·띄어쓰기·중복 후보를 묶고 검토 | 이름이 비슷하다는 이유만으로 다른 지점을 자동 병합하면 안 됨 |
| Python CSV 처리 + pyproj/PROJ | 파일별 필드 통일, 원 좌표계에서 WGS84로 변환, 이상 좌표 탐지 | 좌표계·축 순서가 틀리면 오차가 생김. 원본 CRS를 명시 |
| Tesseract 같은 로컬 OCR | 사용 가능한 메뉴 사진의 이름·가격을 초안으로 추출 | OCR 결과는 숫자·옵션·분량을 사람이 확인. 이미지에서 읽었다고 1인 가격이 확정되지는 않음 |
| 팀원의 소규모 수동 검증 | 시연 코스의 위치·영업·가격 기준 확인 | 검증 시점과 출처를 남기고 결과를 별도 패치 파일에 기록 |

[OpenRefine](https://openrefine.org/), [pyproj](https://pyproj4.github.io/pyproj/stable/), [Tesseract](https://github.com/tesseract-ocr/tesseract).

AI는 이름 매칭 후보·분류·메뉴 파싱을 도울 수 있지만, 없는 금액·별점·영업시간을 생성해서 검증된 값으로 채우는 도구로 사용하지 않는다.

## 7. 무료로 확정하지 못했거나 이번에 제외한 것

- 레드테이블의 지자체 인증 식당 메뉴 데이터는 확인한 상품 페이지에서 **유료**로 표시된다. 무료 미리보기와 전체 이용권을 구분한다. [확인한 상품](https://www.bigdata-culture.kr/bigdata/user/data_market/detail.do?id=c957e3c0-0547-11ec-8e60-2bcdc8456bfb)
- Google·네이버·카카오 리뷰를 수집한다는 제3자 서비스는 공식 API와 다르다. 무료 체험·수집 가능·영구 보관 가능을 같은 의미로 보지 않는다.
- 블로그 검색 결과는 영수증·방문자 리뷰 전체나 검증된 평점을 대신하지 않는다.
- KOPIS 공연·공연장 정보는 확장 후보지만, 이번에는 공식 안내 페이지의 본문을 읽지 못해 무료 조건·상세 필드를 확정하지 않았다. TourAPI와 시설 표준자료를 우선한다. [공식 안내](https://www.kopis.or.kr/por/cs/openapi/openApiInfo.do?menuId=MNU_00077)
- LOCALDATA 홈페이지 직접 열기는 시간 초과였다. 영업 상태 기능은 확인 가능한 행정안전부 공공데이터포털 API/파일을 근거로 평가했다.
- 유가·식재료 시세·지역 평균 외식물가를 개별 가게 가격으로 전환하는 방법은 사용하지 않는다.

## 9. 채택할 데이터 구조

원본은 바꾸지 않고 별도 시연 자료에 다음 정보를 관리하는 안이다.

- 장소: 독립 ID, 원본 ID, 상호, 지점, 정규화 주소, 건물·층·호, 원 좌표와 좌표계, 사용할 WGS84 좌표, 활동 분류.
- 가격: 통화, 최소·최대, 단위, 기준 메뉴·티켓, 무료 여부, 가격 미확인 여부, 수준만 있는지 여부.
- 출처: 값별 원문 URL·원본 기준일·수집일·검토일·보관 가능 여부.
- 매칭: 이름만 일치 / 이름+주소 일치 / 지점 확인 / 사람이 확인 / 모호함 등 근거.
- 영업: 행정 상태와 실제 운영 확인을 구분.
- 외부 정보: 저장을 허용하는 공급자 식별자·링크와 조회 전용 정보를 분리.
- 리뷰: 제공자·척도·리뷰 수·기준일을 구분. 출처가 다른 점수를 단순 평균하지 않음.

동일 건물의 다른 가게·다른 지점·같은 상호의 별개 업소를 합치지 않는다. 원본 충돌은 한쪽을 조용히 덮어쓰지 않고 검토 목록으로 남긴다.

## 10. 예상 총비용 범위 규칙

**1인 기준으로 확인된 범위만 인원수와 곱한다.**

- 식사: 식사로 볼 수 있는 1인 메뉴 기준. 사이드·추가·주류·단체 세트 금액을 자동 포함하지 않음.
- 카페: 선택한 기준 음료 1잔. 음료+디저트라면 그 구성도 표시.
- 문화: 성인 입장권 1장. 할인·공연 회차·기간별 금액을 구분.
- 무료: 근거가 있는 무료만 0~0원.
- 미확인: 0원이 아니라 값 없음.
- 수준만 있음: ‘저렴/보통/높음’ 같은 표시만 하고 임의의 원화 범위를 만들지 않음.
- 상한 없음: 유한한 최대금액으로 표시하지 않음.

예시(설명용 가상 금액): 식사 1인 10,000~15,000원 + 음료 4,000~6,000원 + 입장료 0~0원, 2명 → **예상 총비용 28,000~42,000원**.

가격 미확인 장소가 한 곳이라도 있으면 ‘전체 비용 확정 범위’처럼 표현하지 않는다. 예: **확인된 비용 28,000~42,000원 + 가격 미확인 1곳**.

1인 상한 10,000원 조건에서 8,000~15,000원인 후보는 확실히 조건을 충족한다고 표시하지 않는다. 기본은 최대금액까지 조건 안에 드는 후보를 우선하고, 미확인·상한 초과 가능은 명시한다.

현재 Place.price / RoutePlan.totalCost / 추천 가격 필터 / 저장 스냅샷은 단일 정수 가격을 전제로 한다. 화면 문자열만 바꾸면 안 되고, 가격 모델·추천 비교·합계·저장 구조를 함께 바꿔야 한다. 이번 검토에서 해당 코드는 아직 변경하지 않았다.

## 11. 추천 실행 순서

1. 별도 서면·전포 테스트 폴더를 만들고 원본 해시·설정·출처를 기록한다.
2. 기존 부산 공공자료에서 후보를 추린다. 문화시설은 행정동이 아닌 주소·좌표를 함께 사용한다.
3. 착한가격업소 + 부산맛집정보 + TourAPI를 먼저 추가 검토한다.
4. 인허가 자료로 폐업·이름·주소 충돌을 점검하고, 좌표계·지점·중복을 정리한다.
5. 1인 비용 기준이 확인되는 장소부터 작은 시연 코스 세트를 만든다. 확인되지 않은 항목은 채우지 않는다.
6. 가격 범위 모델과 전체 화면·추천·저장 계산을 맞춘다.
7. Google은 소수 장소에서 필요한 정보의 제공률을 시험하되, 원본 영구 보강과 분리하고 실제 표시·보관 설계를 먼저 확인한다.
8. 부족한 문화·위치 정보만 OSM·Overture·FSQ·Wikidata로 보완 검토한다. 전부 도입하지 않는다.

추천 우선 조합: **보유 공공자료 + 부산 메뉴 API/CSV + 부산맛집정보 + TourAPI + 인허가 자료 + 소규모 수동 확인**. 무료 수단을 많이 붙이는 것보다 출처·단위·매칭이 분명한 작은 시연 세트를 만드는 것이 우선이다.

## 변경 범위

이번 검토에서는 이 문서만 새로 추가했다. 실제 인증 API 호출·신규 데이터 적재·기존 원본 덮어쓰기·앱 코드 수정은 수행하지 않았다. 팀 문서 사이트 배포나 보드 상태 변경도 하지 않았다.
