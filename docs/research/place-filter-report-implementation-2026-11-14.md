## 구현한 흐름

1. 장소 목록에서 **서면 공공자료 · 추정 가격**을 선택한다. 기존 DB 목록과 기존 9곳 시연 목록은 그대로 유지한다.
2. 코스 편집 화면에서 활동·1인 가격 상한·직선 반경을 같은 위치에서 조정한다. 가격은 만원 표시를 유지하며 `0.7`=7,000원, `0.82`=8,200원을 입력할 수 있다. 화살표·스크롤은 1,000원씩 조절한다.
3. 선택 사항인 세부 조건을 펼쳐 종류와 특징을 고른다. 현재 태그는 근거가 있는 착한가격·무료입장만 제공한다.
4. **후보 업데이트**를 누른다. 전체 범위와 이전 장소 반경의 교집합, 가격, 세부 종류, 태그, 중복 제외를 모두 적용한 뒤 가까운 순으로 표시한다.
5. 후보 표시 수를 5/10/20/30곳으로 바꾼다. 일치 개수와 실제 표시 개수를 구분하며, 기존 조건과 표시 범위 안의 선택 후보를 유지한다.
6. 입력을 바꾸면 이전 후보는 남지만 업데이트 전에는 추가할 수 없다. 비동기 조회 중 초기화·조건 변경 시 늦은 응답은 버린다.
7. 후보 카드의 가격 근거는 `부산 착한가격업소 기준 추정 가격`처럼 짧게 안내한다. 상세 화면은 출처 URL·자료일·확인 정보를 별도 필드로 늘어놓지 않고 간략 설명으로 요약한다. 자세한 산식과 출처는 내부 데이터에 보존한다.
8. 장소 추가·편집 완료·저장·다시 열기까지 가격의 추정 상태와 태그를 보존한다.
9. 로그인한 회원은 장소 **상세 정보 카드의 정보 정정 제보**에서 가격/업종/이름/주소의 수정안과 이유를 제출한다. 후보 목록의 제보 버튼은 제거했다.
10. 실제 관리자 로그인 화면의 **장소 정보 제보** 탭에서 접수 내용을 읽고 승인 값·검토 메모를 입력해 승인하거나 반려한다.
11. 승인 정보만 다음 **후보 업데이트**부터 반영한다. 기존 저장 코스는 저장 당시 snapshot을 유지한다.

## 가격과 태그 처리

`PriceEstimate`는 금액 형태와 근거 종류를 분리한다. 기존 참고 가격, 공개 자료, Google 제공, 유사 장소 추정, 시연 가정, 관리자 검토, 미확인을 표현할 수 있다. 이전 JSON에 근거 종류가 없어도 기존 참고 가격으로 복원한다.

추정값은 숫자로 계산하지만 총비용에 추정 장소 수를 함께 표시한다. 추정값이 들어간 코스를 확정 총액으로 반환하지 않는다. 상한 판정은 범위 가격의 최대값을 사용하며, 추정값에 의한 판정임을 카드·후보 상태에 표시한다. 가격 미확인 포함은 추정값 활용과 다른 설정이다.

태그에는 지정/계산의 근거·출처·자료일이 함께 있다. 지정 근거 없이 모범음식점을 붙이거나, 가격 미확인을 무료로 바꾸거나, 직선거리를 도보 시간으로 표시하지 않는다. 모범음식점·교통 접근성은 타입을 준비했지만 실제 근거 자료는 아직 연결하지 않았다.

## 정정 데이터와 관리자

`place_information_reports`에 신청자·장소·필드·기존 값·제안 값·이유·근거·처리 상태·검토 메모·실제 승인 값을 저장한다.
`place_information_overrides`에 승인된 필드만 저장한다. 원본 데이터와 저장 코스는 수정하지 않는다.

동일한 공공 장소 ID를 가진 기존/확장 시연 목록은 정정값을 공유한다. 이름만 비슷한 다른 가게에는 적용하지 않는다. 승인·정정 저장은 트랜잭션이며 중복 처리는 거절한다. 반려와 잘못된 승인 값은 장소를 변경하지 않는다.

관리자 제보 화면은 임시 Fake 리뷰 화면과 분리해 실제 Swing 관리자 창의 탭으로 연결했다. 기존 로그인 메서드에 AdminSession을 생성하는 경로가 없어, 저장된 app_admins 해시 검증 후에만 해당 세션을 발급하도록 연결했다. 관리자 자격 증명은 변경하지 않았다.

주소 정정은 표시 주소만 바꾼다. 좌표 자동 변경은 포함하지 않았으며 제보 폼에서 안내한다. 이미 저장한 코스의 가격을 최신 승인값으로 자동 갱신하지 않는다.

현재 실행을 막는 API 키 요청이나 필수 확인은 없다. 다음은 다음 작업 범위를 정할 때 함께 선택하면 된다.

## 추가 지도 대조와 대표 시연 흐름

기존 공통 키로 Google Places의 이름·주소·좌표·영업 상태·유형만 메모리에서 비교했다. [Text Search 공식 문서](https://developers.google.com/maps/documentation/places/web-service/text-search)의 필드 마스크를 사용하며 가격·리뷰는 요청하지 않았다. 최초 4회, 문화 대체 후보 3회, 행정구 비교 수정 후 2회로 총 9회다. API 키와 원문 응답은 저장하거나 출력하지 않았다. 외부 ID와 자체 판정·사유·확인 시각만 별도 JSON에 남겼다.

- 대조 통과: 대모골, 카페이떼, 파노라믹커피부산, 증권박물관(부산관).
- 보류: 부산포민속박물관(주소·운영 상태 재확인), 한국거래소자본시장역사박물관(주소 재확인), 부산여대차박물관(이름·활동 유형 재확인).
- 보류는 폐업 확정이라는 뜻이 아니다. 확장 추천 목록에서만 제외하며 원본 공공 CSV와 기존 코스는 보존한다.
- 서면 반경에 남구 장소도 포함되는데, 초기 검사에서 부산진구를 고정한 오류가 있었다. 원본 주소의 구를 비교하도록 수정하고 두 곳을 재대조했다. 시간순으로 가장 최근 판정을 사용한다. 같은 오류가 재발하지 않도록 오프라인 Python 테스트 3개도 통과했다.

`tools/check_rehearsal_places.py`는 수동 검증 도구다. 출력 파일/호출 잠금이 있으면 재호출하지 않는다. 확장 JSON 재생성은 최신 대조 판정을 반영하며 추가 API를 호출하지 않는다.

자동 리허설은 **대모골 → 카페이떼 → 증권박물관(부산관)**으로 수행했다. 두 사람 기준 식사 7,000원·음료 2,400원·공공자료상 성인 관람료 0원을 사용한 예상 총비용은 18,800원이며 추정 장소 2곳을 표시한다. 실제 매장 가격을 보장하는 시나리오가 아니다.

H2 테스트 DB에서만 식당 가격을 9,500원으로 가상 제보·승인했다. 승인 후 7,000원 조건에서는 해당 식당이 제외되고, 9,500원 조건에서는 다시 나타나는지 확인했다. 기존 저장본은 18,800원을 유지하며, 명시적으로 수정 저장하면 23,800원과 추정 장소 1곳으로 바뀐다. 실제 팀 DB의 장소 가격은 바꾸지 않았다.

이 리허설은 직선 범위·후보 계산·저장·정정 흐름의 검증이다. 예약 가능 여부·개별 이용 조건·당일 개관 시간·실제 도보 이동을 검증한 것은 아니다. 재현 결과는 Git 제외 `build/rehearsal/public-course.md`에 생성된다.

## 상세 카드 정리와 장소 추가별 도보 시간

사용자 피드백에 따라 가격 근거는 `부산 착한가격업소`처럼 짧게 표현하고, 출처·장소 확인은 하단 한 문단으로 요약했다. URL·자료일·표본 수·산식은 카드에서 제외했다. 후보와 내 코스 목록의 제보 버튼은 상세 카드로 옮겼다. 지도 브리지는 현재 표시 중인 코스/후보 ID만 찾아 제보 폼을 연다.

편집에서 장소를 추가·삭제·재정렬하거나 코스를 다시 열면 출발지부터 확정한 장소들까지 TMAP 도보 경로를 자동 조회한다. 후보를 눌러보는 것만으로는 자동 조회하지 않는다. 기존 구간은 서비스의 5분 캐시를 재사용하고 바뀐 구간만 요청한다.

내 코스의 각 장소에 `도보 약 N분 · 누적 약 M분`, 편집 상단에 최근 구간과 누적 도보 시간을 표시한다. 편집 완료 화면에도 누적 시간을 표시한다. 누적은 초 단위로 합산한 뒤 분으로 올림하며, 체류시간은 제외한다. 실패·초기화·코스 변경 시 이전 경로의 시간이 남지 않게 무효화하고 늦게 도착한 응답을 버린다. 시간은 DB snapshot에 추가하지 않고 코스를 열 때 다시 조회하므로 저장 형식은 유지된다.

자동 시간 계산은 지도 SDK 로드와 분리했다. 지도가 준비되지 않아도 TMAP 시간이 먼저 표시되고, 지도 연결이 완료되면 경로를 그린다. 실제 연동 테스트는 대모골 1곳 → 카페이떼 포함 2곳 순서로 실제 TMAP 시간과 합계를 확인해 통과했다. 실행 중인 사용자 앱의 8080 포트는 건드리지 않았으며, 테스트용 임시 포트의 카카오 SDK 로드는 실패해 실제 카카오 지도 렌더링까지 확인했다고 주장하지 않는다. 상세 카드·제보·지도 경로 표시 동작은 실제 페이지와 SDK fixture로 검증했다.

실호출 재현: `gradlew.bat tmapLiveTest --tests '*editorAutomaticallyShowsActualTmapTimesAfterAddingConfirmedStops' --no-daemon`.
화면 캡처: `build/ui-preview/detail-card-concise.png`, `walking-editor-times-live.png` (Git 제외).

## 불필요한 조작 제거와 버튼 정리

공통 조건·코스 편집의 수동 **도보 경로** 버튼과 상단 **경로 설명** 버튼을 제거했다. 자동 조회는 유지한다. 실패했을 때는 지도 새로고침 후 경로를 다시 요청하도록 연결했다.

경로 설명 데이터와 내부 처리 기능은 보존하고, 지도 경로 hover 팝업에 해당 구간의 안내만 표시한다. 다른 구간을 hover하면 그 구간의 설명으로 바뀌고, 마우스를 떼면 고정 선택으로 돌아간다. 팝업 안으로 이동해 긴 안내를 읽고 스크롤할 수 있으며, 그 스크롤은 지도 확대·축소에 전달하지 않는다. 상단 전체 경로 설명 패널을 별도로 열 필요가 없다.

편집 화면의 **편집 초기화**는 확인창 없이 편집 장소·도착 반경·후보를 비운 뒤 기존 편집 완료 콜백으로 빈 코스를 적용한다. 공통 조건 화면으로 돌아오며 출발지·인원·전체 범위는 유지된다. 기존 저장 코스를 DB에서 삭제하는 기능은 아니다.

일반 동작 버튼의 높이는 36px, 글자는 13px, 모서리는 8px로 통일하고 여백을 공통화했다. 주요 동작은 분홍색, 보조 동작은 중립색으로 표현한다. 폭은 문구에 따라 달라지며 숫자 증감 화살표·알림 닫기·지도 핀 같은 소형 조작부는 크기 예외를 둔다. 지도 내부 검색·상세 버튼도 같은 기준을 사용한다.

자동 초기화→빈 코스 적용→공통 조건 복귀, 해당 구간만 보이는 긴 설명, 팝업 유지·스크롤·지도 확대 방지를 검증했다. `top-five-candidates.png`, `walking-leg-tooltip.png` 캡처에서도 배치를 확인했다. 이번 작업에서는 API나 DB 데이터 변경 없이 UI와 연결 흐름만 수정했다.

## 지도·목록 선택 연결과 단계별 UX 검토

정보 정정 제보는 상세 카드 하단의 작은 텍스트 링크로 낮추고, 편집 중 추천 후보의 상세 카드에는 **코스에 추가**를 제공한다. 이미 코스에 들어간 장소나 공통 조건 화면의 장소에는 추가 버튼을 표시하지 않는다. 조건을 바꾸거나 후보 조회 중이면 카드 추가도 비활성화한다. 링크 클릭은 외부 브라우저 이동과 구분하며 기존 제보 폼을 연다.

지도 후보를 클릭하면 우측 후보 목록의 선택·키보드 포커스·스크롤을 해당 행에 맞춘다. 후보 영역이 스크롤 밖에 있으면 그 영역도 보이게 이동한다. 상세 카드 추가는 목록 추가와 같은 처리로 연결했으며, 두 번 누르기·옛 후보·이미 추가한 후보는 중복 추가하지 않는다. JavaScript에서 들어온 이벤트는 다음 JavaFX 이벤트에서 처리해 지도 표시 중 재진입을 피한다.

| 단계 | 숨기는 항목 | 유지하거나 비활성화하는 항목 |
|---|---|---|
| 공통 조건에서 코스가 없을 때 | 저장, 도보 설정, 변경할 내용이 없는 초기화 | 출발지·인원·전체 범위와 코스 만들기 |
| 편집을 시작해 장소·후보가 없을 때 | 빈 내 코스 영역, 전체 코스 보기, 도보 설정, 편집 초기화 | 조건 입력, 돌아가기. 새 빈 코스의 완료는 비활성화 |
| 후보 선택 중 | 조건에 맞지 않는 활동별 옵션 | 목록·지도·상세 카드 추가를 같은 후보 상태로 연결 |
| 코스의 장소를 선택하기 전 | 선택 장소의 반경 슬라이더 | 이동·삭제·상세 버튼은 선택 전 비활성화해 조작 위치를 유지 |
| 기존 코스를 모두 비운 상태 | 빈 내 코스 영역 | 빈 결과를 적용할 수 있도록 편집 완료는 유지 |
| 자동 도보 조회 중 | 전체 화면을 가리는 대기 UI | 시간 조회 상태만 표시하고 다음 후보 선택을 계속 허용 |

종류가 하나뿐이거나 선택할 태그가 없는 필드는 숨기고, 두 필드 모두 선택지가 없으면 세부 조건 영역 자체를 숨긴다. 아직 동작하지 않는 ‘커뮤니티 · 준비 중’ 상단 메뉴도 숨겼다. 로그인 사용자 메뉴는 고정 높이에 비해 큰 세로 여백을 줄이고 내부 라벨 여백을 정리해 글자 잘림을 보완했다. 1200px 화면에서 사용자 이름·드롭다운 배치를 확인했다.

추가 검증: 지도에서 30번째 후보 선택 시 목록 선택·포커스 동기화, 카드 추가·중복·옛 후보 차단, 제보 링크, 사용자 메뉴 글자 영역, 초기 단계 표시를 확인했다. `detail-card-concise.png`, `user-menu-and-initial-actions.png`에 캡처가 있다. API 호출·DB 스키마 변경은 추가하지 않았다.


## 단일 패널 탐색과 후보 행 정리

내 코스 보기·다음 장소의 조건·추천 후보 중 한 영역만 펼친다. 현재 제목을 눌러도 닫히지 않고 다른 제목을 선택해서 전환한다. 조회 성공 시 후보, 추가 후에는 조건, 거리 오류 시에는 내 코스로 이동한다. 빈 후보 영역은 비활성화한다. 조건과 후보는 패널 전환 시 유지한다.

후보 행의 상세·추가 버튼을 제거했다. 행을 한 번 클릭하거나 Enter를 누르면 지도 상세 카드를 열고, 추가는 카드의 기존 동작으로 처리한다. 지도에서 선택했을 때 목록 선택·포커스를 맞추는 연결도 유지한다.

내 코스의 반경 설명에 장소를 추가할 당시 ‘다음 장소의 조건’에서 정했던 값이며 해당 구간만 수정한다는 문구를 넣었다. 다음 장소의 반경 상한은 전체 반경 + 출발지에서 직전 장소까지의 직선거리로 계산하고 100m 단위로 올림한다. 기존 모델의 최대 2,000m를 유지하며, 조건 변경 시 다음 반경만 상한으로 조정한다. 기존 장소에 기록된 반경은 자동으로 바꾸지 않는다.

ModernScrollPane 공통 클래스를 만들고 FormScrollPane이 상속한다. 공통 조건·편집 폼과 관리자 제보 상세에 적용했다. 목록·표·텍스트 입력의 내부 스크롤바도 같은 CSS를 사용한다. 스크롤바는 8px 공간을 확보하고 얇은 둥근 손잡이를 표시한다. 사용자 메뉴는 기존에도 실제 이름 + ‘님’을 사용하므로 이름 데이터는 변경하지 않았다.

검증: 전체 자동 테스트 207개 통과(실패·오류 0), JAR 빌드 성공. 실제 JavaFX 후보 행 클릭으로 상세 카드 호출, 버튼 제거, 단일 패널 전환·현재 패널 닫기 차단, 전체 반경 변경 시 상한 조정과 기존 반경 보존, 반경 기하 계산을 확인했다. 후보 화면 캡처로 버튼 제거와 얇은 스크롤바를 확인했다. 지도 배경은 테스트 대역이며 실제 지도 API를 재호출하지 않았다.


## 경로 설명 팝업 가독성 보완

경로 hover 팝업은 기본 폭을 248px에서 360px로 늘리고 지도 폭보다 최소 24px 작게 제한한다. 제목 14px·본문 13px, 명시적 글자색·줄바꿈, 안내별 간격과 구분선을 적용했다. 긴 공백 없는 안내도 가로로 넘치지 않는다. 안내 영역에는 얇은 스크롤바를 사용하고 전체 팝업 높이는 지도 높이 - 24px(최대 420px)로 제한한다. 오버레이 앵커와 위치 계산을 맞춰 지도 가장자리에서도 12px 여백을 확보한다.

같은 구간에서 마우스가 움직이면 안내 DOM을 다시 만들지 않아 읽던 스크롤 위치가 유지된다. 다른 구간으로 전환할 때만 내용과 스크롤을 초기화한다. 기존 구간별 안내·hover 유지·지도 확대 방지 동작은 유지했다. 지도 WebView 안의 팝업 리소스만 변경했으며 Java 서비스와 데이터 구조는 그대로다.

검증: 전체 207개 테스트 통과, JAR 빌드 성공. 긴 한국어·공백 없는 안내의 가로 넘침, 스크롤 위치 보존, SDK 유사 부모 스타일 상속 차단, 280×240 지도에서 팝업 크기와 투영 좌표 경계, 다른 구간 내용 분리를 확인했다. build/ui-preview/walking-tooltip-readable.png에 JavaFX WebView 테스트 화면을 기록했다. 실제 지도 API가 아닌 SDK 대역으로 검증했다.


## 경로 호버·클릭 구분 및 지도 카드 닫기

호버 팝업은 구간명·거리·시간과 상세 안내 유도 문구만 보여주는 280px 요약이다. 클릭하면 최대 360px의 상세 이동 안내로 전환하고 고정한다. 고정된 안내는 다른 구간 호버로 바뀌지 않으며 다른 구간 클릭으로 전환한다. 닫기 버튼·Escape·지도 빈 곳 클릭으로 닫는다. 상세 스크롤 위치는 같은 구간에서 유지한다.

지도 빈 곳 클릭은 경로 팝업과 장소 상세 카드를 모두 닫는다. 둘 중 하나라도 열린 상태라면 해당 클릭을 닫기에 사용하고 출발지는 바꾸지 않는다. 기존 경로 클릭 이벤트의 지도 클릭 전파 방지도 유지한다.

구간 번호 원형 아이콘은 각 paths에 실제로 그려진 선분 길이를 합산해 절반 지점을 보간하고, 아이콘 중심을 그 좌표에 맞춘다. 좌표 개수·경로 분할에 따른 치우침과 구간 순번에 따른 세로 오프셋을 제거했다.

검증: 전체 208개 테스트 통과, JAR 빌드 성공. 호버 요약·클릭 상세 전환, 다른 구간 호버 시 고정 유지, 마우스 이탈·닫기, 두 카드 동시 닫기와 출발지 보존, 불균일한 좌표 샘플과 복수 paths의 길이 중간점 배치를 SDK 대역으로 검증했다. 실제 지도 API 추가 호출은 없었다.


## 공통 조건 초기화와 편집 상태 문구

공통 조건의 코스 초기화는 인원 2명·전체 반경 500m·출발지 미선택으로 되돌리고 코스·저장 연결을 비운다. 선택한 장소 목록은 유지한다. PlannerMap이 현재 계획·후보·대기 상세·도보 요청을 비우고, 지도 WebView도 마커·원·경로·팝업·검색어를 제거한 뒤 초기 부산 중심과 확대 수준으로 돌아간다. 지도 준비 전 초기화는 준비 완료 시 적용하며, 이후 재연결에서 이전 출발지를 Java로 다시 전달하지 않는다.

단일 선택되는 편집 패널의 열린 제목은 Java에서 일반 커서를 유지하고 다른 제목에는 손 모양 커서를 둔다. 내부의 선택 사항 패널은 별도 동작을 유지한다. JavaFX 스킨 제목의 생성과 커서 재설정을 감시하므로 레이아웃 후에도 열린 패널 커서가 바뀌지 않는다. 후보가 없을 때는 ‘후보 검색’, 결과가 있으면 ‘후보 업데이트’를 표시하고, 추가·초기화로 후보가 비워지면 다시 검색으로 돌아간다.

검증: 전체 211개 테스트 통과, JAR 빌드 성공. 공통 초기화 버튼의 기본값 복원과 출발지 재선택 요구, 지도 도형 제거·브리지 재연결·다시 위치 선택, 열린/닫힌 제목의 실제 커서, 후보 버튼명 전환을 확인했다. 사용자 이름 공백 수정은 유지했다.
