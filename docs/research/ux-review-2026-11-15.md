# 현재 UX 전문가 평가 (2026-11-15)

## 평가 범위와 방식

실행 중인 `데이트 코스 · 서면·전포 시연` JavaFX 앱을 약 1440×960 크기에서 직접 조작했다. 공통 조건 → 기본 후보 검색 → 가격 미확인 포함 후 재검색 → 후보 상세 카드 → 장소 추가 → 내 코스 보기/구간 선택 → 편집 완료를 확인했다. 로그인 없는 9곳 시연 목록 기준이며 로그인 사용자 정보, 실제 저장/삭제, 127곳 공공 목록의 태그·가격 표시, 작은 창과 키보드 전체 탐색은 이번 직접 평가 범위에 포함하지 않았다. 아래는 사용자 모집 기반의 사용성 실험 결과가 아니라 관찰에 근거한 전문가 평가다. 코드 변경 없이 수행했다.

## 종합 판단

지도 조작, 단계별 조건 입력, 장소 추가 후 다음 조건으로 이동, 최근/누적 도보 시간은 일관된 작업 모델을 제공한다. 가장 큰 개선 여지는 화면 간 공간 배치, 현재 상태에 맞는 안내, 검색 실패에서의 회복, 완성 후 검토 화면이다. 기능을 추가하기보다 이미 있는 기능을 언제 어디에 보여줄지 정리하는 편이 효과적이다.

## 직접 관찰한 문제와 제안

| 높음 | 공통 조건은 왼쪽 패널/오른쪽 지도인데 편집은 왼쪽 지도/오른쪽 패널이다. | 화면 전환 때 지도와 조작 위치를 다시 찾아야 한다. | 공통 조건과 편집의 패널 방향 및 지도 위치를 고정한다. 어떤 방향을 택할지는 전체 화면 요구에 맞추되 일관성을 우선한다. |

| 보통 | 출발지가 이미 선택됐어도 공통 조건에는 출발 위치를 선택하라는 안내가 남아 있고, 자동 도보 경로 표시 후에도 경로 조회를 요청하는 과거 안내가 남는다. | 무엇이 완료됐고 다음에 무엇을 해야 하는지 서로 다른 메시지가 나온다. | 미선택/선택/편집/완료 상태별 안내를 한 기준으로 갱신한다. 예: 선택한 출발지 요약, 다음 단계 안내, 경로에 마우스를 올려 안내 확인. |

## 유지할 요소

- 부드러운 지도 이동과 지도/장소의 공간 관계를 유지하는 방향.
- 내 코스/다음 조건/추천 후보 중 하나만 펼치는 구조. 특히 장소 추가 후 다음 조건으로 자동 이동하는 흐름.
- 상세 카드의 코스 추가 행동과 보조적인 정보 정정 제보 링크. 후보 목록에 별도 추가/상세 버튼을 다시 늘릴 필요는 없다.
- 최근 이동과 누적 도보 시간의 병기, 체류시간 제외 안내.
- 선택한 구간의 반경을 수정할 때 이전에 정한 다음 장소 조건이라는 설명.

## 권장 적용 순서

1. 오래된 안내 문구, 카드 가독성, 가격 정보 중복을 먼저 수정한다.
2. 빈 결과에서 실제 원인을 알려주고 조건을 선택적으로 완화할 수 있게 한다.
3. 공통/편집 화면의 패널 위치를 통일하고 완료 상태에서는 코스 검토를 우선한다.
4. 가격 단위와 추천 근거 표현을 다듬는다.

변경 후에는 처음 쓰는 사용자에게 출발지 선택부터 장소 두 곳 추가·코스 검토까지 설명 없이 수행하게 하고, 첫 장소 추가까지의 시간, 0건 결과에서 회복 여부, 편집 완료와 저장의 구분, 조건과 결과를 오간 횟수를 관찰하면 된다. 이번 평가에서는 이러한 사용자 지표를 측정하지 않았다.
