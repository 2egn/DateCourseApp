# 핀 입력 상태와 단일 활성화 (2026-11-15)

## 처리 구조

PinPointerGesture는 누름·이동·뗌과 해당 입력에서 파생된 후속 클릭만 관리한다. 지도 SDK, DOM, 타이머, 장소명이나 ID에 의존하지 않는다. map.js는 좌표 판정 및 SDK 이벤트를 이 객체에 연결하고 상세 열기 명령과 hover 표시를 담당한다.

- 누를 때 판정한 핀을 입력 대상으로 유지한다. 누름 중에는 hover 이탈 예약을 취소하고 표시 대상 교체를 유예한다.
- 이동 허용 범위 안에서 손을 떼면 기억한 핀의 상세 열기 명령을 직접 실행한다. DOM 대상 교체 때문에 최종 click이 생기지 않아도 동작한다.
- SDK의 click 알림과 최종 DOM click은 같은 입력의 후속 알림으로 구분해 중복 실행하지 않는다. 임의의 밀리초 동안 차단하는 방식은 사용하지 않는다. 새 누름이나 키보드 입력으로 상태를 초기화한다.
- 이동 허용치를 한 번 넘으면 원래 위치로 돌아와도 드래그로 유지한다. 입력 도중 제거된 핀이나 명시적인 다른 UI에 손을 뗀 경우에는 실행하지 않는다.
- 지도 SDK 원시 이벤트인 visitClick과 앱의 명령인 openDetails를 분리한다. 완료된 입력이 own command를 실행한 뒤 같은 SDK 알림이 다시 와도 중복 실행되지 않는다.

## 설정과 수명

PIN_INPUT에 캔버스 크기·기준점·hover 이탈 여유·입력 이동 허용치·hover 닫기 지연을 모았다. 이미지 인식 영역과 좌표 판정도 같은 값을 사용한다. 이동 허용치는 화면 조작 정책이며 특정 장소나 시연 상황에 대한 분기가 아니다.

MapPageServer가 새 JS 상태 객체를 제공하며 map.html에서 map.js보다 먼저 로드한다. 이 서버는 앱 시작 때 리소스를 메모리에 읽으므로 적용 확인 시 앱을 완전히 재실행해야 한다. 지도 다시 불러오기만으로 이전 JVM의 리소스가 바뀌지는 않는다.

## 검증 범위

전체 261개 테스트 및 JAR 빌드 통과. 두 재현 테스트는 수정 전 실패하고 수정 후 통과했다.

- 누르는 동안 움직임·SDK 이탈·지연 대기에도 hover 유지.
- 누른 DOM 노드를 제거하고 다른 노드에서 mouseup만 전달해도 상세 열기.
- 후속 SDK click과 DOM click이 와도 지도 이동/상세 열기는 한 번만 실행.
- 드래그했다가 시작 지점으로 돌아와도 상세가 열리지 않음.
- 새 입력을 반복하면 매번 한 번 활성화할 수 있고 시간창에 의존하지 않음.
- 새 상태 객체 리소스가 앱 내 서버에서 제공됨.

검증은 WebView의 DOM 이벤트 및 SDK fixture를 사용했다. 현재 실행 중인 로컬 지도 서버는 없어 실사용 SDK 화면의 직접 클릭은 검증하지 못했다.
