화면에는 결과·현재 단계·다음 행동을 표시한다. DB/HTTP 원문 오류, 키, 접속 주소와
내부 예외 메시지는 사용자 안내에 붙이지 않는다. 입력 검증 안내는 사용자가 수정할
수 있도록 유지한다. 가격의 추정/미확인 상태와 지도 출처도 유지한다.

- 저장 진행: 지도 준비 → 미리보기 생성 → 코스 저장.
- 부분 실패: 코스 저장 완료 여부와 미리보기 재시도 위치를 한 알림에 표시한다.
  부분 성공은 정보 알림이며 성공 알림으로 전부 완료된 것처럼 표시하지 않는다.
- 알림은 첫 문장 이후를 버리지 않는다. 짧은 안내와 행동 문구를 함께 표시한다.
- 장소 목록 선택은 기본 접힌 추가 설정에 두며, 불러온 장소 수는 바로 표시한다.
  가격 데이터 구성은 툴팁에서 확인할 수 있다.
- 저장한 코스에서 미리보기 없음을 감지하면 ‘미리보기 만들기’ 링크를 제공한다.
  이미지 조회 실패는 ‘다시 불러오기’로 구분한다.

## 미리보기만 재생성

별도 지도 창은 기존 PlannerMap의 준비/직선 경로 캡처를 재사용하고 도보 API를 호출하지
않는다. 취소/닫기/Escape 시 캡처 자원을 정리한다. 생성한 PNG는 refreshPreview에서
코스 소유권과 현재 저장 내용의 해시를 검증한 뒤 이미지 테이블만 변경한다.
코스 제목·수정 시각·방문 장소·유저 코스 목록 캐시는 변경하지 않는다.
다른 창에서 코스가 수정됐다면 이전 내용의 이미지 저장을 거절한다.

## 콘솔 진단

`AppDiagnostics`는 `datecourse.diagnostics` System.Logger에 구조화된 한 줄을 기록한다.
실패/부분 실패는 WARNING, 정상 완료/취소는 DEBUG다. 기본 콘솔을 과도하게 채우지 않는다.
예:

```
operation=COURSE_SAVE ref=012345abcdef stage=MAP_CAPTURE outcome=PARTIAL elapsed_ms=1200 error=IOException location=com.datecourse.controller.PlannerMap.capturePreview:200
```

기록 항목은 작업 종류, 임의 참조 번호, 단계, 결과, 경과 시간, 예외 유형과 앱 코드 위치다.
가능한 경우 SQL 상태/오류 번호와 HTTP 응답 번호를 추가한다. 원문 Throwable 메시지,
SQL 문장/매개변수, 경로·URL·토큰·API 키·비밀번호·이메일·장소/코스 내용은 출력하지 않는다.
참조 번호는 사용자/코스 ID에서 만들지 않는다.

비동기 폼, 프리뷰 저장/조회, 지도 시작, 도보 응답과 Swing 화면/계정 처리 실패를
연결했다. 모든 외부 라이브러리의 자체 출력까지 대체하는 로깅 설정은 아니다.

검증: 오류 메시지에 접속 URL/키/이메일을 넣어도 로그 문자열에 포함되지 않는지,
부분 실패 알림·진행 단계·접힌 설정·이미지 단독 갱신·소유권·변경 충돌·취소·캐시 유지,
실제 지도 재생성과 창 자원 정리를 확인한다.
