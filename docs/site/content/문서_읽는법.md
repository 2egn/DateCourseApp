## 먼저 어떤 순서로 읽으면 좋을까요?

관심 있는 기능 하나를 고른 뒤, **사용자 행동 → 화면 담당 코드 → 계산·조회 코드 → 결과 데이터** 순서로 따라가 보세요. 처음부터 모든 클래스와 Java 문법을 외울 필요는 없어요.

예를 들어 ‘카페를 추천받는 과정’이 궁금하다면 다음 네 곳이면 시작할 수 있어요.

1. [[02_화면/RouteEditorController|RouteEditorController]]: 사용자가 다음 장소의 조건을 입력하고 추천 버튼을 눌러요.
2. [[03_처리/NextPlaceService|NextPlaceService]]: 거리·활동·가격 조건에 맞는 후보를 골라요.
3. [[04_데이터/Place|Place]]: 후보 한 곳의 이름·위치·가격을 담아요.
4. 다시 편집 화면: 후보를 보여주고, 사용자가 고른 한 곳을 추가해요.

앱을 실행해 보려면 [[실행_및_테스트|처음 실행하기와 테스트]], 전체 그림이 궁금하면 [[전체_동작_흐름|전체 동작 흐름]], 파일 위치를 찾으려면 [[목차|클래스 목차]]로 가세요.

## 클래스 문서는 이렇게 읽어요

**‘한눈에 보기’와 ‘사용 장면과 읽는 순서’를 먼저 읽으세요.** 이 코드가 필요한 이유와 실제로 이어지는 과정을 설명해요.

그다음 함수표에서 방금 나온 이름을 찾아보세요. 모든 표를 외우기보다, 지금 따라가는 기능에 필요한 함수 몇 개만 보면 돼요. 흐름도에서는 같은 함수를 찾아 화살표를 따라가고, 함수 위에 마우스를 올리거나 키보드로 선택하면 짧은 설명도 볼 수 있어요.

마지막으로 ‘핵심 코드’를 읽어 보세요. 실제 원본에서 가져온 일부이므로 긴 함수의 준비·나머지 처리까지 모두 보이지 않을 수 있어요. ‘일부 발췌’라고 적힌 코드는 그것만 복사해 실행하는 예제가 아니에요.

| 문서의 부분 | 여기서 알아볼 것 |
|---|---|
| 한눈에 보기 | 이 클래스가 앱에서 맡은 일 |
| 사용 장면과 읽는 순서 | 어떤 상황에서 시작해 어디로 이어지는지 |
| 주요 메서드 | 함수가 받거나 바꾸는 값, 돌려주는 결과 |
| 라이브러리·API 표 | 직접 만든 코드가 어떤 준비된 도구를 쓰는지 |
| 흐름도와 핵심 코드 | 설명이 실제 함수·문장 어디에 해당하는지 |
| 주의할 점 | 예전 코드·예제·아직 연결되지 않은 기능인지 |

## 클래스·객체·메서드는 무엇인가요?

**클래스**는 관련 정보와 동작을 한 파일 안에서 묶어 정의한 코드예요. 예를 들어 Place는 장소 정보를 담는 모양이고, NextPlaceService는 다음 장소를 고르는 동작을 담아요.

그 정의대로 실제로 만들어 사용하는 하나를 **객체**라고 해요. ‘장소 정보를 담는 모양’은 Place 클래스이고, 그 모양으로 만든 ‘어떤 식당 한 곳의 정보’는 Place 객체라고 생각하면 돼요.

**메서드**는 클래스 안의 함수예요. 괄호 안으로 필요한 값을 받고, 일을 한 뒤 결과를 돌려줄 수도 있어요. 예를 들어 `NextPlaceService.candidates(...)`는 NextPlaceService의 candidates 함수를 부른다는 뜻이에요. 함수가 돌려주는 결과를 ‘반환값’이라고 불러요.

**생성자**는 새 객체를 만들 때 처음 값을 준비하는 코드예요. `new Place(...)`에서 괄호 안으로 장소의 이름·좌표·가격 등을 넘겨요.

## 값을 담는 방식: List·Map·record·enum

**List**는 순서가 있는 목록이에요. 코스가 식당→카페라면 두 장소의 순서도 정보예요. 순서를 바꾸면 실제 방문 순서가 달라져요.

**Map**은 어떤 번호와 그에 해당하는 값을 연결하는 표예요. 이 프로젝트의 `Map<Long, Integer>`는 ‘장소 번호 → 허용 거리’ 같은 관계를 나타내요. 단순히 첫 번째·두 번째 값으로 읽는 List와 용도가 달라요.

**record**는 여러 값을 짧게 묶는 Java 문법이에요. `Place.name()`처럼 저장한 값을 읽는 함수가 자동으로 생겨요. 다만 record 안에 List가 들어 있다고 그 목록까지 자동으로 복사되는 것은 아니에요. RoutePlan은 목록·거리 표를 복사해 원래 코스와 편집본을 분리해요.

**enum**은 정해진 선택지를 모은 타입이에요. WalkingSearchOption은 도보 길찾기의 네 가지 방식을 담아요. 아무 문자열이나 받는 대신 제공하는 선택지 중 하나를 쓰게 해줘요.

## 화면과 처리 코드가 연결되는 방식

**컨트롤러(Controller)**는 화면의 입력·버튼·표시를 연결하는 담당자예요. **서비스(Service)**는 추천이나 거리 검사 같은 처리를 맡고, **저장소 담당 코드(Repository)**는 DB에서 자료를 읽거나 써요. 이름은 역할을 찾는 단서예요. 실제 담당 범위는 각 문서에서 확인하세요.

**FXML**은 JavaFX 화면의 배치를 적어 둔 파일이에요. `@FXML`은 화면의 입력칸·버튼 동작을 Java 코드에 연결할 때 만나는 표시예요.

**Swing과 JavaFX**는 Java 화면을 만드는 두 도구예요. 이 앱은 Swing 로그인에서 JavaFX 코스 화면으로 이어져요. **WebView**는 JavaFX 안에 웹 지도를 띄우는 화면 부품이에요. 지도 안에서는 JavaScript가 실행돼요.

**콜백(callback)**은 ‘나중에 이 일이 생기면 실행해 주세요’ 하고 넘겨 둔 동작이에요. 편집 화면에 완료·취소 콜백을 넘겨 두면, 사용자가 해당 버튼을 눌렀을 때 메인 화면의 동작을 실행할 수 있어요.

| 자주 보이는 표현 | 읽는 방법 |
|---|---|
| `->` | 나중에 실행할 짧은 동작을 적는 람다식이에요. |
| `::` | 이미 있는 함수를 실행할 동작으로 넘기는 표현이에요. |
| `return` | 함수를 끝내요. 뒤에 값이 있으면 그 값을 호출한 쪽에 돌려줘요. |
| `if (...) return;` | 해당 조건이면 그 자리에서 함수를 끝내고 뒤의 처리는 하지 않아요. |
| `try (...)` | DB 연결·파일처럼 쓰고 정리해야 하는 자원을 마치면 자동으로 닫아요. |
| `stream → filter → map → toList` | 목록을 읽기 시작하고 → 조건에 맞는 것만 남기고 → 모양을 바꾸고 → 결과 목록으로 모아요. |

## 기다리는 작업과 화면을 바꾸는 작업

**스레드(thread)**는 프로그램 안에서 일을 진행하는 실행 흐름이에요. DB나 외부 길찾기 응답을 화면 담당 흐름에서 오래 기다리면 버튼·화면도 멈출 수 있어요.

그래서 오래 걸리는 일을 별도 작업으로 보내고, 결과가 오면 화면을 바꾸도록 연결해요. 결과를 기다리는 동안 다른 일을 계속할 수 있는 처리를 **비동기**라고 불러요. Swing 화면을 바꾸는 곳과 JavaFX 화면을 바꾸는 곳도 구분해야 해요. `SwingWorker.done()`과 `Platform.runLater()`는 이 구분을 할 때 만나요.

**이전 응답 차단**도 중요해요. 식당 상세를 요청했다가 곧바로 카페를 골랐다면, 늦게 도착한 식당 결과가 카페 화면에 붙으면 안 돼요. 결과를 반영하기 전에 아직 같은 선택·코스인지 확인하는 이유예요.

## 저장·지도·테스트에서 만나는 말

| 용어 | 이 프로젝트에서의 뜻과 예 |
|---|---|
| DB·SQL | 정보를 남기는 저장소와, 그 자료를 읽거나 바꾸는 요청 문장이에요. |
| JSON·파싱 | 이름과 값으로 적힌 데이터 형식과, 그 글자를 읽어 Java 값으로 바꾸는 과정이에요. |
| API·SDK | 다른 프로그램에 요청하는 약속과, 그 기능을 연결하는 데 쓰는 도구 모음이에요. |
| 캐시 | 같은 요청을 반복하지 않도록 이전 결과를 잠시 보관하는 것이에요. 키·옵션·두 지점이 다르면 같은 도보 요청으로 보면 안 돼요. |
| 반경·교집합 | 중심에서 허용하는 거리와, 두 범위를 동시에 만족하는 영역이에요. 추천 후보는 전체 범위와 이전 장소 범위를 모두 만족해야 해요. |
| 트랜잭션·commit·rollback | 여러 DB 변경을 한 묶음으로 처리하고, 모두 확정하거나 실패한 묶음을 취소하는 방식이에요. |
| 동기화·무효화 | 두 곳의 내용을 맞추기와, 조건이 바뀌어 더 이상 맞지 않는 이전 결과를 쓰지 않기예요. |
| 단위 검사·통합 검사·회귀 검사 | 한 기능 확인 / 여러 기능을 연결해서 확인 / 원래 되던 기능이 여전히 되는지 재확인이에요. |
| 모의 객체·H2 | 실제 외부 서비스 대신 시험용 응답을 주는 코드와, 테스트에 쓰는 DB예요. 실제 카카오·운영 DB 성공과 구분해야 해요. |
| 해시·salt | 비밀번호 원문 대신 비교할 값을 계산하는 방식과, 같은 비밀번호도 저장 결과가 달라지게 넣는 무작위 값이에요. |

## 현재 코드·예전 코드·아직 만들 기능을 구분해요

**현재 사용**은 통합 앱의 실행 흐름에서 쓴다는 뜻이에요. 그 클래스와 관련된 모든 기능이 완성됐다는 뜻은 아니에요.

**예제·데모**는 화면을 먼저 확인하려고 미리 만든 자료를 넣을 수 있어요. **이전 코드**는 현재 사용자 흐름과 다른 설계예요. 예를 들어 현재 코스는 RoutePlan, 예전 화면은 Course·CoursePlace를 사용해요. 이름이 비슷해도 가격 기준과 저장 방식이 같다고 생각하면 안 돼요.

특히 **편집 완료 → 메인 화면 반영**과 **DB 저장 → 앱을 다시 켠 뒤 불러오기**는 다른 단계예요. 현재 구현 상태는 해당 문서의 기준 버전과 작업 보드를 함께 확인하세요.

## 개발 중인 문서의 기준과 갱신 방법

초기 클래스 노트는 2026-11-11 작업본의 `ce1cd24`까지의 흐름을 설명해요. 이후 `d32bc76` 기준의 지도 서버·도보·로딩 클래스 7개와 실행 안내를 추가했어요. 2026-11-13에는 내용을 읽기 쉽게 풀어썼으며, 이것이 앱 코드가 새로 구현됐다는 뜻은 아니에요.

문서의 `source`는 원본 파일 위치예요. `source_sha256`은 설명할 당시 원본의 지문이고, 현재 파일과 다르면 설명을 다시 확인해야 해요. 코드 줄 번호도 개발 중 바뀔 수 있어요.

기능을 바꾸면 해당 클래스 설명·함수표·코드 발췌를 고치고, 호출하는 클래스와 [[전체_동작_흐름|전체 흐름]]도 함께 확인해요. 테스트 통과 수는 실제 실행한 결과가 있을 때만 바꿔요. 실제 DB 비밀번호·지도 키·개인 로그인 기록은 문서에 넣지 않아요.
