장소 갱신·비활성 처리·변경 이력을 200건씩 묶어 전송해요. 원본 버전 검사, 적재 잠금과 전체 트랜잭션은 유지해요.

- `PlaceCatalogRepository.synchronize()`: 바뀐 행을 모아 실행하고 마지막 나머지도 처리.
- `addBatch()` / `flushBatches()`: SQL 매개변수 수집과 실행, 실패 전달.
- `DatabasePool.create()`: MySQL 드라이버 배치 전송 활성화.

<summary>검증과 남은 범위</summary>

405곳의 여러 묶음에 대해 갱신·비활성·재활성·기존 번호·이력을 확인했어요. 마지막 이력 쓰기가 실패하면 먼저 실행한 묶음까지 모두 롤백돼요. Java 370개(유지보수 3개 포함)가 통과했어요.

새 장소의 자동 생성 ID 연결은 기존 개별 처리를 유지해요. 운영 MySQL 속도 비교는 아직 하지 않았어요. 이전 가격 보완 시간은 이 구현의 측정 결과가 아니에요. 이번 문서 수정만으로 게시 사이트가 갱신되지는 않아요.
