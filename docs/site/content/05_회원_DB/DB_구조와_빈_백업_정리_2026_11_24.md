사용자 승인 후 비어 있는 이전 백업 8개만 제거해 운영 테이블은 23개에서 15개가 됐어요. 남은 15개 테이블의 스키마와 실제 행은 전후 동일해요.

```text
운영 DB · 15개
├─ 회원·관리자
│  ├─ members
│  └─ app_admins
├─ 원본 자료
│  ├─ categories
│  └─ data_records
├─ 장소 카탈로그
│  ├─ place_catalog_sources
│  ├─ place_catalog_entries
│  ├─ place_catalog_imports
│  ├─ place_catalog_revisions
│  └─ place_catalog_lock
├─ 저장한 코스
│  ├─ saved_courses
│  ├─ saved_course_places
│  ├─ saved_course_previews
│  └─ saved_course_transport
└─ 정보 정정
   ├─ place_information_reports
   └─ place_information_overrides
```

<details>
<summary>현재 장소·가격을 보는 위치</summary>

현재 장소는 `place_catalog_entries` 2,040행이며 모두 활성 상태예요. `record_id`가 `data_records`에 연결되고, `payload`의 JSON 문자열에 장소 정보·`priceEstimate`·`details`를 저장해요. 가격의 실값·추정·미확인, 분류·태그·외부 ID·근거를 여기서 구분해요.

`data_records`는 총 8,179행이에요. 현재 카탈로그 연결 2,040행과 그 외 원본 6,139행을 보존했어요. `categories`는 원본 자료의 분류이며 음식 종류 필터와 같은 의미는 아니에요.

저장 장소는 `saved_course_places`의 당시 스냅샷이에요. 현재 장소·정정값이 바뀌어도 저장한 코스 내용을 자동으로 덮어쓰지 않아요. 승인한 정정은 `place_information_overrides`로 현재 원본 위에 적용해요.

</details>

<details>
<summary>정리한 대상과 복원·검증</summary>

`categories_backup_*` 4개와 `data_records_backup_*` 4개만 제거했어요. 쓰기 잠금 후 0행과 외래 키·뷰·트리거 참조 부재를 재확인했고, 외래 키 검사는 유지했어요. 원본·회원·코스·이미지·교통수단·제보·정정·적재 이력은 바꾸지 않았어요.

저장소 `archive/db-schema/2026-11-24-empty-backups/`에 고정 대상 목록·사전 검사·완료 결과·재생성 SQL을 보관했어요. 원래 빈 테이블이므로 보관한 데이터 행은 없어요. 빈 테이블의 엔진·문자셋·인덱스를 재생성할 수 있어요.

`ReplaceIntegratedData`의 이후 백업 생성 기능은 유지해요. 이번 승인은 지정한 이전 백업 8개에 한정돼요. 사이트 원본 갱신과 실제 게시 사이트 배포는 별개예요.

</details>
