일반 앱의 시작·제보·코스 저장·카탈로그 적재에서 자동 DDL을 제거했어요. 기능 브랜치 작업이며 운영 DB 실행·master 반영·사이트 배포는 별도예요.

## 역할과 실행

| 위치·메서드 | 역할 |
|---|---|
| `maintenance.DatabaseSetup.prepare()` | 관리자가 명시적으로 회원·관리자·제보·카탈로그·이미지·이동수단 추가 구조를 준비 |
| `db.DatabaseSchema` | 실제 회원 행을 읽지 않는 0행 조회로 구조 확인, 누락 시 준비 안내 |
| 저장소의 기존 `initialize()` 계열 | 공개 이름은 유지하며 구조 조회만 수행 |
| `page.account.StartupPanel` | 구조 미준비를 연결 오류와 구분해 관리자에게 준비를 요청하도록 안내 |

기본 `02`·`07` 구조와 `08` 가격 스냅샷 확장이 준비된 DB에 `./gradlew.bat setupDatabase`를 명시적으로 실행해요. DB 자체 생성과 일회성 `08`·`13` 마이그레이션, 원본 교체·장소 적재는 이 명령에 포함하지 않아요. 이미 준비된 운영 DB는 이번 코드 변경 때문에 다시 준비할 필요가 없어요.

부분 범위는 `--args="--membership"`, `--reports`, `--catalog`, `--previews`, `--transport`로 선택해요. 기존 `setupInformationReports`·`setupCoursePreviews` 작업 이름과 `demo`의 직접 실행 경로는 새 명령으로 위임해요.

관리자 테이블이 없을 때 생성하고 초기 계정이 없을 때만 등록해요. 기존 관리자 비밀번호·회원·장소·저장 코스는 덮어쓰지 않아요. MySQL DDL은 전체 롤백되지 않을 수 있어 실패 시 상태 확인 후 재실행해야 해요.

## 유지한 동작과 검증

- 준비된 DB에서는 구조 변경 권한 없이 로그인 준비·제보·코스 저장이 가능해요.
- 이미지 테이블이 없으면 코스 본문 저장은 유지하고, 과거 코스 조회는 이미지 없이 열려요. 이동수단 테이블이 없는 과거 코스의 도보 기본값도 유지해요.
- H2 격리 DB에서 시작 시 자동 생성·열 확장 차단, 반복 준비의 계정·코스·제보 보존, DDL 권한 없는 일반 실행을 확인해요.
- 앱 372개·선택 유지보수 3개, 보관 예제 2개를 검사해요. 실제 공급사·운영 DB와 배포는 실행하지 않아요.
