---
title: 도보 설정과 지도 경로 동기화
reviewed_at: 2026-11-25
---

편집 지도에서 도보 탐색 방식을 바꾼 뒤 같은 코스를 메인 지도에 표시해도 옛 경로가 남던 문제를 수정했어요. 이번 개선은 기능 브랜치 작업이며 운영 master 배포와 구분해요.

`TmapSettings.saveSearchOption()`·`saveLocal()`은 설정 파일 교체가 성공한 뒤 실행 중 설정 버전을 올려요. 저장 실패나 잘못된 입력은 버전을 바꾸지 않아요. `CourseMapView.synchronizeWalkingRoute()`는 방문 순서·이동수단과 함께 이 버전을 비교해요. 코스를 다시 표시하거나 경로를 요청하면 다른 화면에서 바꾼 설정도 반영해요.

- 메인·편집의 자동 조회 지도는 옛 경로를 지우고 새 조건으로 다시 조회해요.
- 저장한 코스 지도는 옛 결과를 지우고 안내하지만, 실제 이동 경로는 사용자가 다시 요청해야 해요. 목록·장소 표의 시간 캐시도 설정 버전을 확인해 옛 도보 시간을 표시하지 않아요. 목록을 새로 읽으면 목록에서 사라진 코스의 시간 캐시를 정리해요.
- 설정 변경 전에 요청한 결과가 늦게 성공하거나 실패해도 최신 경로·오류 안내를 덮어쓰지 않아요.
- 자동차 경로는 도보 설정 변경으로 다시 요청하지 않아요. 대중교통+도보는 도보 구간을 포함하므로 변경을 반영해요.

새 이벤트 버스·백그라운드 감시·테이블 없이 기존 지도 요청 번호와 취소 처리를 사용해요. 설정 버전은 같은 앱 프로세스 안에서 성공적으로 저장한 변경만 알려줘요. 별도 앱 프로세스나 사용자가 파일을 직접 편집한 변경을 실시간 감시하지 않아요. 공급사 키는 지도 JavaScript에 전달하지 않아요.

회귀 검사는 임시 폴더의 설정 저장과 모의 경로 계산기로 두 지도 재표시, 늦은 응답 차단·자동 재조회, 저장 지도의 명시적 조회 유지, 자동차 경로 재사용을 확인해요. 실제 TMAP·카카오 호출과 운영 DB 변경은 포함하지 않아요.

검증 결과: 앱·선택 유지보수 Java 393개와 보관 UI 2개 통과, JAR 생성 완료.
