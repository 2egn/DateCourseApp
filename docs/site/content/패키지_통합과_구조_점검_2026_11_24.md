---
title: 패키지 통합과 구조 점검
reviewed_at: 2026-11-24
---

현재 앱·검사를 `com.datecourse`로 통일하고 공용 UI 위치를 정리했어요. Java 27개와 검사 18개를 옮겼으며 화면 동작·DB 형식·공급사 호출 방식은 유지해요. 과거 보관 원본과 문서의 코드 발췌는 그대로 남겨요.

```text
com.datecourse
├─ app                       AppLauncher
├─ auth                      PasswordHash
├─ db                        회원·장소·저장 코스 저장소와 DB 설정
├─ maintenance               ReplaceIntegratedData
├─ model                     장소·코스·경로·UserSession
├─ page
│  ├─ _01step_planner
│  ├─ _02step_editor
│  ├─ _03step_saved
│  ├─ account                로그인·회원가입·내 정보
│  ├─ admin                  회원 관리
│  ├─ review                 장소 제보 검토
│  └─ common
│     ├─ controls            JavaFX 필터·스크롤·대화상자 부품
│     ├─ map                 공통 지도·브리지
│     └─ swing               Swing 스타일·대화상자·입력 부품
├─ service                   추천·경로·설정·표현·사용자 캐시
└─ demo                      단독 시연과 기존 검증·관리 명령
```

<details>
<summary>주요 파일·참조 변경</summary>

| 이전 위치 | 현재 위치·역할 |
|---|---|
| `kr.ac.university.localdb.db` | `com.datecourse.db`: 저장소와 기존 DB 설정·초기화 |
| 옛 `ui`의 회원 화면 | `page.account`: `MembershipApp`, `SignupForm`, 시작·로딩 화면 |
| 옛 `ui`의 관리자 화면 | `page.admin`: `MemberAdminPanel`, `AdminStyle` |
| 옛 `ui`의 공용 부품 | `page.common.swing`: `LoginUI`, `AppDialogs`, `RevealPanel`, `CapsLockHint` |
| `com.datecourse.ui` | `page.common.controls`: JavaFX 필터·스크롤·대화상자 스타일 |
| 옛 루트의 `UserSession` | `model.UserSession`: 로그인 사용자 식별값 |
| 옛 루트의 `PasswordHash` | `auth.PasswordHash`: 비밀번호 해시 |
| 옛 루트의 `ReplaceIntegratedData` | `maintenance.ReplaceIntegratedData`: 명시적 데이터 교체 명령 |

- `AppLauncher.main()`: 새 위치의 `MembershipApp` 호출. 통합 진입점 이름은 같아요.
- `AdminStyle.tabs()`: 회원 진입 화면에서도 쓰는 관리자 탭 스타일에만 공개 접근을 허용해요. 내부 색상·나머지 보조 메서드는 기존 범위예요.
- `AppDiagnostics.format()`: 앱 스택 위치를 `com.datecourse` 기준으로 찾아요.
- `build.gradle`, `tools/catalog-ops/verify.init.gradle`: 관리 명령·적재 검증 클래스 경로를 갱신해요. 작업 이름은 같아요.
- `tools/place-data-pilot/pilot.py`: 보호 대상 저장소 파일 경로를 갱신해요.
- FXML의 공용 부품 import·검사 패키지·현재 안내·클래스 노트의 `current_source`를 함께 갱신해요. 과거 `source_commit`·`source_sha256`은 유지해요.
- `archive/legacy-ui/verify.init.gradle`: 보관 원본 대신 검사 복사본의 DB 패키지를 맞춰 컴파일해요. 보관 SHA는 유지해요.

</details>

<details>
<summary>다른 패키지의 구조 점검과 후속 우선순위</summary>

| 판단 | 근거·권장 조치 |
|---|---|
| 다음 정리 후보: `service` | 29개 클래스에 추천·경로 조회·키 설정·화면 표현·캐시가 섞여 있어요. 기능을 수정할 때 `place`·`route`·설정·표현 묶음을 순차적으로 정리하는 편이 좋아요. 모든 클래스에 하위 폴더를 강제할 필요는 없어요. |
| 의존 방향 개선 후보: `db.AdminPasswordReset` | 비밀번호 재설정 명령이 Swing 입력 UI를 직접 사용해요. 명령을 `maintenance`로 분리하는 것이 적절하지만 비공개 풀 생성·재설정 검사와 함께 옮겨야 해요. 이번에는 기존 공개 범위를 불필요하게 넓히지 않고 경로만 통일했어요. |
| 이름 개선 후보: `demo` | 시연뿐 아니라 `PublicPlaceImport`, `CoursePreviewSetup`, `InformationReportSetup` 같은 실제 관리 명령도 있어요. 후속으로 관리 명령은 `maintenance`, 단순 시연은 `demo`로 분리하면 실행 목적이 명확해져요. |
| 경계 개선 후보: `service` ↔ `db` | `UserContext`는 `MemberRepository.Profile`을 쓰고, DB는 `PlaceSource`·범위 검증·키 로딩을 사용해 패키지 의존이 양방향이에요. 현재 단일 앱에서 오류를 뜻하지는 않지만, 기능별 분류 때 공유 계약·정책의 위치를 함께 검토해야 해요. 인터페이스를 대량으로 추가할 필요는 없어요. |
| 유지: `model` | 화면 패키지·JavaFX·Swing에 직접 의존하지 않아요. 공유 데이터를 페이지 안으로 옮기지 않아요. |
| 유지: 페이지별 Java·FXML | 같은 페이지 경로를 사용하고 지도는 여러 화면이 공유해요. Gradle 표준 `java`·`resources` 분리를 유지해요. |
| 유지: `MembershipApp`의 화면 연결 | 로그인 후 회원·관리자·코스 화면을 연결하는 진입 역할이 있어요. 현재 콜백·세션·종료 순서를 보존하고, 역할 분리가 필요해질 때 별도로 검토해요. |

</details>

<details>
<summary>검증 범위</summary>

- JDK 21에서 앱 367개·선택 유지보수 3개, 보관 예제 2개 통과.
- 파일을 참조하는 장소 데이터 도구 Python 검사 51개·사이트 검사 55개 통과.
- JAR에 옛 `kr/`·`com/datecourse/ui/` 항목이 없고, FXML 5개의 컨트롤러·공용 import 클래스가 포함돼 있어요.
- 게시용 문서 143개를 로컬 빌드했어요.
- 실제 공급사 API·운영 DB 변경·문서 사이트 재배포는 수행하지 않았어요.

</details>
