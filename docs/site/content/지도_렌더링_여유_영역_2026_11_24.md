---
title: 지도 렌더링 여유 영역
reviewed_at: 2026-11-24
---

짧은 드래그에서 지도 일부가 늦게 채워지고 경계의 마커·선이 사라지는 현상을 줄이기 위해, 보이는 창보다 SDK 지도를 크게 렌더링해요. 기능 브랜치 작업이며 실제 타일 환경의 개선 폭은 별도 시연으로 확인해야 해요.

## 배치와 입력

- `#map`은 보이는 지도 영역이고 바깥을 잘라내요. 검색·상세 카드·구간 안내는 기존 크기와 위치를 유지해요.
- `#map-canvas`가 실제 SDK 지도를 담아요. 사방으로 보이는 폭·높이의 25%씩, 각 방향 최대 256px을 추가해요. 타일의 영구 저장이나 별도 다운로드는 하지 않아요.
- `map-viewport.js`가 SDK 픽셀 좌표와 보이는 화면 좌표 사이의 여백을 보정해요. 마커 우선 입력·호버·휠 확대 중심·범위 안내는 보이는 좌표를 사용해요.
- `camera-motion.js`는 보이는 영역으로 전체 코스와 검색 반경을 맞춰요. SDK 렌더링 폭이 커졌다는 이유로 확대 수준을 바꾸지 않아요.
- SDK 하단 고정 로고·출처 요소는 원래 노드를 유지한 채 안쪽으로 배치해요. 타일 패널처럼 상하단을 모두 채우는 요소는 이동하지 않아요. SDK DOM 구조 변경은 실제 시연 시 확인해야 해요.
- 저장 이미지 캡처 중에는 여유 영역을 일시 해제하고 전체 원본 지도를 찍은 뒤 복원해요.

기본 마커·경로 투명도와 호버·선택 강조 정책은 유지해요. 화면 가장자리만을 이유로 투명도를 더 낮추는 처리는 없어요. 큰 이동이나 확대 수준 변경, 느린 네트워크에서는 새 타일을 기다릴 수 있어요. 렌더링 면적 증가는 최대 약 2.25배이며 추가 타일·메모리를 사용해요.

## 위치와 검증

| 위치 | 책임 |
|---|---|
| `map-viewport.js` | 여유 영역·화면 좌표 변환·SDK 하단 표시 배치 |
| `map.js` | SDK 연결·기존 입력과 호버·캡처 모드 연동 |
| `camera-motion.js` / `instant-zoom.js` | 보이는 크기 기준 카메라와 확대 중심 |
| `MapPageServer` | 새 지도 스크립트 제공 |

모의 SDK와 실제 JavaFX WebView로 화면 경계의 마커 선택, 확대 중심, 창 크기 변경 후 중심·수준 유지, 하단 출처 표시, 캡처 중 해제·복원을 검사해요. 기존 장소·경로·카메라 회귀 검사도 유지해요. 실제 공급사 타일 로딩 시간과 경계 소실 개선은 모의 검사만으로 확정하지 않아요.

크기 변경 후 재배치와 픽셀 좌표 기준은 [Kakao Map.relayout](https://apis.map.kakao.com/web/documentation/#Map_relayout), [MapProjection](https://apis.map.kakao.com/web/documentation/#MapProjection)을 참고해요.

검증 결과: Java 전체 381개(앱 378·선택 유지보수 3), 보관 예제 2개 통과. JAR 생성도 통과했어요. 실제 공급사 호출 없이 모의 SDK에서 확인한 결과예요.
