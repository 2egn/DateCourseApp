앱을 만들 때 모든 기능을 처음부터 직접 작성하지는 않아요. 화면·DB 연결·JSON 읽기처럼 자주 필요한 기능은 미리 만들어진 도구인 **라이브러리**를 사용해요.

## ea2242b에서 추가·연결한 사용처

| 도구 | 함수 | 실제 용도 |
|---|---|---|
| JavaFX `Task`, Java `Callable` | `BasePageController.runWork()` | 화면을 멈추지 않고 DB 작업 후 성공·실패를 UI에 전달 |
| JavaFX `Timeline`, `FadeTransition` | `PageFeedback.show()` | 알림의 남은 시간 바와 사라짐 애니메이션 |
| JDBC `PreparedStatement`, `Connection` | `SavedCourseRepository.persist()`, `findAll()` | 회원별 SQL 조회·트랜잭션 저장·롤백 |
| Jackson `ObjectMapper` | `readPlaceSnapshot()`, `PilotPlaceRepository.read()` | 저장한 가격·출처와 시연 JSON을 객체로 복원 |
| Java `Instant`, `DateTimeFormatter` | `SavedCourseController.updatedText()` | DB 수정 시각을 한국 시간으로 표시 |
| Swing `Toolkit`, `Timer` | `CapsLockHint.refresh()` | 비밀번호를 읽지 않고 Caps Lock 상태 확인 |
| Java `List.copyOf`, `Map.copyOf` | `RoutePlan` 생성자 | 화면 간 전달한 장소·반경 목록의 원본 보호 |

[[현재_구현_흐름|현재 코드 흐름]]과 각 클래스의 함수표를 함께 읽어 주세요. 아래 내용은 기존 도구의 배경 설명이에요.

예를 들어 PlaceRepository가 DB 글자를 Place로 바꿀 때 Jackson을 쓰고, DatabasePool은 DB 연결을 재사용하기 위해 HikariCP를 써요. 이 문서는 ‘무슨 도구를 어느 함수에서 왜 쓰는지’ 찾아보는 안내예요.

**처음에는 아래 도구별 역할과 JSON·DB 예시부터 읽으세요.** 뒤의 API별 긴 표는 관련 클래스나 함수 이름을 찾을 때 참고하면 돼요. `import`는 도구의 이름을 코드에서 짧게 쓰기 위한 선언이고, 필요한 도구를 내려받도록 정하는 설정은 `build.gradle`에 있어요.

## 먼저 구분할 세 가지

- **JDK 기본 기능:** Java를 설치하면 함께 제공하는 목록·파일·Swing·DB 요청 규칙 등이에요.
- **추가 라이브러리:** JavaFX·Jackson·HikariCP처럼 프로젝트가 추가로 준비하는 도구예요. ‘의존성’은 이 앱이 필요로 하는 이런 도구를 뜻해요.
- **빌드 도구와 플러그인:** 앱을 만들고 실행·검사할 준비를 도와줘요. 화면에서 호출하는 함수 라이브러리와는 역할이 달라요.

`org.openjfx.javafxplugin` 0.1.0은 JavaFX 의존성·실행을 돕는 **Gradle 플러그인**이다. 앱에서 호출하는 Java 메서드 라이브러리가 아니다. Java application 플러그인도 빌드/실행 도구다.

## JDK에 이미 포함된 API

| API | 쉬운 설명 | 실제 예 |
|---|---|---|
| Swing·AWT (`java.desktop`) | 로그인 화면·그리기·파일 밖 브라우저 실행 | MembershipApp.show(), UiTheme.field()/button(), ExternalBrowser.open() |
| JDBC (`java.sql`, `javax.sql`) | 연결·SQL·결과 행 표준 API | MemberRepository.login(), PlaceRepository.findAll() |
| Collections / Stream | 목록·대응표·필터·정렬 | NextPlaceService.candidates(), RoutePlan.totalCost() |
| 파일·Properties | 설정·로컬 기록·SQL 파일 | DbSettings.load(), InputHistory.save(), ReplaceIntegratedData.main() |
| 스레드·함수형 인터페이스 | 작업 분리와 완료 동작 전달 | MembershipApp.run(), ConditionController.loadPlaces(), MapBridge 콜백 |

SwingWorker.done()은 Swing 화면 스레드에서, Platform.runLater()는 JavaFX 화면 스레드에서 실행한다. 두 UI의 스레드를 서로 바꾸어 사용하면 안 된다.

## JSON과 DB 연결은 이렇게 읽기

```text
DB 행(data_payload 문자열)
  → PlaceRepository.findAll()
  → ObjectMapper.readTree()
  → JsonNode의 name/lat/lon/price 읽기
  → new Place(...)

RoutePlan
  → PlannerMap.render()
  → ObjectMapper.writeValueAsString()
  → WebView.executeScript()
  → map.js의 presentRoute()
```

DB 조회를 세 역할로 나눠 보면 쉬워요. **JDBC**는 Java에서 SQL을 보내고 결과를 받는 공통 약속, **Connector/J**는 그 약속대로 MySQL과 실제로 통신하는 도구, **HikariCP**는 이미 만든 연결을 빌려 쓰고 돌려받는 관리자예요.

**Jackson**은 JSON을 읽고 쓰는 도구예요. DB에서는 JSON 글자를 Java 값으로 읽고, 반대로 지도에 보낼 때는 Java 코스를 JSON 글자로 바꿔요. 아래 긴 표의 readTree·writeValueAsString이 그 두 방향이에요.

## Java 라이브러리가 아닌 지도 구성

카카오 지도 SDK는 웹 지도 기능을 연결하는 JavaScript 도구예요. JavaFX의 WebView가 그 웹페이지를 앱 안에 보여줘요. Java 쪽에서는 PlannerMap·MapBridge를 거쳐 코스와 지도 선택 정보를 주고받아요.

d32bc76에서는 [[03_처리/MapPageServer|MapPageServer]]가 지도 파일을 제공하는 작은 서버를 자동으로 켜요. 초기 버전에서 쓰던 별도 Python 서버와 실행 방법을 혼동하지 마세요. TMAP 도보 요청은 [[03_처리/WalkingRouteService|WalkingRouteService]]의 Java HTTP 요청으로 처리해요.

## 수정 시 확인

의존성 버전은 build.gradle과 실제 해석 결과가 기준이다. 문서 작성만으로 라이브러리를 업그레이드하지 않았다. Java 파일의 import뿐 아니라 생성자·필드·콜백에서 사용되는 API도 함께 확인한다.
