> **현재 실행 기준:** ea2242b. 07·08 SQL은 새 로컬 DB에서 한 번 실행해요. 기존 DB에 08을 반복 실행하지 않아요. 아래 이전 버전 설명은 기록이에요.

> **이전 기준 버전:** `d32bc76` 리뷰 대상. 이전 `ce1cd24`는 수동 지도 서버 방식이며 실행법이 다르다. 변경 요약은 [[업데이트_내역|업데이트 내역]]에서 확인한다.

> Windows에서 `2egn/DateCourseApp` 저장소를 clone한 직후, 개발 도구·개인 설정·DB가 없는 상태를 기준으로 한다. 개발 중인 프로젝트이므로 실행 경로나 기능이 바뀌면 이 안내도 함께 갱신한다.

## 시작 전에: 무엇을 준비하는 건가요?

이 안내는 다른 팀원의 설정 파일을 받지 않고, 저장소에서 프로젝트만 내려받은 PC를 기준으로 해요. 준비 과정은 **Java 도구 → 프로젝트 폴더 확인 → 내 PC의 DB → 지도 키 → 앱 실행** 순서예요.

Java 도구는 프로그램을 만들고 켜기 위해, DB는 회원·장소 자료를 보관하기 위해, 지도 키는 카카오 지도 서비스를 연결하기 위해 필요해요. 각각 다른 설정이므로 로그인은 되는데 지도만 안 보일 수도 있어요.

명령 상자마다 어디에 입력하는지 확인하세요. **PowerShell**은 Windows의 명령 입력 창이고, **mysql>**가 보이는 곳은 MySQL에 접속한 뒤의 SQL 입력 창이에요. 두 창에 입력하는 문장을 섞지 않아야 해요.

## 1. 필요한 도구 설치

| 도구 | 준비할 내용 | 확인 명령 |
|---|---|---|
| JDK | 기준 커밋 README의 Temurin JDK 21. JRE가 아닌 **JDK** 설치 | `java -version`, `javac -version` |
| MySQL | 로컬 MySQL Community Server 8.4와 명령줄 클라이언트 | 아래의 MySQL 접속 단계 |

JDK는 [Temurin 공식 설치 안내](https://adoptium.net/installation)를 따른다. 설치 옵션에서 `PATH`와 `JAVA_HOME`을 설정하고 PowerShell을 다시 연다. `JAVA_HOME`은 JDK 설치 폴더이며 `bin` 폴더 자체가 아니다.

현재 버전은 Java가 지도 서버를 직접 시작하므로 Python 설치는 필요하지 않다.

MySQL은 [Windows 설치 안내](https://dev.mysql.com/doc/refman/8.4/en/windows-installation.html)를 따라 Community Server와 MySQL Configurator를 설치한다. Configurator에서 로컬 서버를 구성하고 포트 **3306**, `root` 비밀번호를 설정한다. 서버를 Windows 서비스로 시작한다. Workbench나 IntelliJ는 필수가 아니다.

Gradle·JavaFX·JDBC 라이브러리는 저장소의 **Gradle Wrapper**가 내려받는다. 별도 Gradle·Maven·JavaFX SDK 설치는 필요하지 않다. 첫 실행에는 인터넷 연결이 필요하다.

## 2. 저장소 폴더와 Java 확인

아직 clone하지 않았다면 다음 명령으로 준비한다. 이미 clone했다면 해당 폴더를 연다.

```powershell
git clone https://github.com/2egn/DateCourseApp.git
cd DateCourseApp
git switch feature/map-integration
```

현재 통합 작업은 `feature/map-integration` 기준이다. 이후 팀에서 사용하는 브랜치가 바뀌면 그 브랜치를 선택한다. 아래 명령은 모두 **`gradlew.bat`가 보이는 프로젝트 루트**에서 실행한다.

```powershell
java -version
javac -version
.\gradlew.bat --version
```

`java`와 `javac`가 JDK 21을 가리키는지, Gradle이 같은 JDK를 사용하는지 확인한다. Wrapper 버전은 `gradle/wrapper/gradle-wrapper.properties`가 정한다.

## 3. 새 로컬 DB와 장소 데이터 준비

**이 단계의 목표:** 내 PC에 앱이 사용할 빈 저장소를 만들고, 추천할 장소 자료를 넣는 것이에요. MySQL은 저장소를 운영하는 프로그램이고 SQL은 그 안의 자료를 만들거나 읽는 명령이에요.

PowerShell에서 MySQL 클라이언트를 연다. 설치 경로가 다르면 경로를 바꾼다. 비밀번호는 `-p` 뒤에 적지 않고 프롬프트에 입력한다.

```powershell
& "C:\Program Files\MySQL\MySQL Server 8.4\bin\mysql.exe" --default-character-set=utf8mb4 -h localhost -P 3306 -u root -p
```

`mysql>` 프롬프트가 보이면 **아래 SQL을 순서대로** 실행한다. `SOURCE`는 clone한 저장소에 있는 SQL 파일을 실행하는 MySQL 명령이다.

```sql
SOURCE data/sql/01_create_database.sql;
USE university_project;
SOURCE data/sql/02_create_tables.sql;
SOURCE data/sql/05_replace_integrated_data.sql;
SOURCE data/sql/07_saved_courses.sql;
SOURCE data/sql/08_saved_course_price_estimates.sql;

SELECT DATABASE();
SELECT COUNT(*) AS place_count
FROM data_records
WHERE source_file = 'integrated_places.csv';
```

선택한 DB가 `university_project`, 장소 수가 **6139**이면 준비된 상태다. SQL 실행 중 오류가 출력되면 다음 단계로 넘어가기 전에 해결한다. 끝나면 `exit`로 클라이언트를 닫는다.

이 절차는 **새 로컬 DB의 첫 준비**용이다. `05_replace_integrated_data.sql`은 지정된 출처의 장소 데이터를 삭제 후 다시 넣는다. 기존 팀 공용 DB의 데이터 교체는 담당자와 별도로 진행한다. 대용량 클라우드 적재용 Java 도구의 백업·묶음 처리 설명은 [[05_회원_DB/ReplaceIntegratedData|ReplaceIntegratedData]]에서 확인한다.

앱 시작 시 회원 관련 초기화가 추가 실행된다. 테이블 생성·변경 권한이 필요하며, 기본 테이블과 장소 데이터가 앱 실행만으로 모두 생성되지는 않는다.

## 4. 내 DB 접속 파일 만들기

**이 단계의 목표:** 앱에 ‘어느 저장소에 어떤 계정으로 연결할지’를 알려주는 것이에요. 앞 단계에서 DB를 만들었다고 앱이 그 주소와 비밀번호를 자동으로 아는 것은 아니에요.

프로젝트에 포함된 예제를 복사한다. clone 직후 실제 설정 파일은 없다.

```powershell
Copy-Item src/main/resources/db.properties.example src/main/resources/db.properties
notepad src/main/resources/db.properties
```

다음처럼 수정하고 저장한다. 비밀번호는 3단계에서 설정한 **내 로컬 MySQL 비밀번호**다.

```properties
db.url=jdbc:mysql://localhost:3306/university_project?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Seoul
db.user=root
db.password=여기에_내_DB_비밀번호
```

`db.properties`는 Git에서 제외된다. `DB_URL`, `DB_USER`, `DB_PASSWORD` 환경변수가 이미 있다면 비어 있지 않은 값이 파일보다 우선한다. 접속 오류가 나면 파일과 환경변수가 서로 다른 서버를 가리키는지도 확인한다.

## 5. 카카오 지도 키 준비

**이 단계의 목표:** 카카오가 이 앱의 지도 사용을 확인할 수 있도록 지도용 키와 사용할 주소를 준비하는 것이에요. 키는 종류가 있으므로 아래의 JavaScript 키를 사용하세요.

1. [카카오 지도 공식 가이드](https://apis.map.kakao.com/web/guide/)에 따라 Kakao Developers 계정에서 앱을 만든다.
2. 해당 앱의 카카오맵 사용 설정을 활성화하고 **JavaScript 키**를 준비한다.
3. 지도 SDK를 사용할 사이트 도메인에 **`http://localhost:8080`**을 등록한다.
4. 아래 명령으로 예제 파일을 복사하고 편집한다.

```powershell
Copy-Item src/main/resources/map/kakao-config.example.js src/main/resources/map/kakao-config.js
notepad src/main/resources/map/kakao-config.js
```

```javascript
window.KAKAO_MAP_KEY = "발급받은_JavaScript_키";
```

REST API 키나 관리자 키가 아닌 JavaScript 키를 사용한다. `kakao-config.js`도 clone에 포함되지 않는 개인 설정 파일이며 새 버전은 실행 시 읽는다. `KAKAO_MAP_JAVASCRIPT_KEY` 환경변수가 우선하며 소스 키가 없으면 `.local/kakao-map.properties`의 `kakao.javascript.key`도 확인한다. 앱은 `localhost` 주소를 쓰므로 허용 도메인을 `127.0.0.1`로만 등록하면 맞지 않는다.

## 6. 앱 실행과 지도 확인

프로젝트 루트의 PowerShell에서 실행한다. 지도 화면을 열면 Java가 `127.0.0.1:8080`에 서버를 자동으로 시작하며 두 지도가 서버 하나를 공유한다.

```powershell
.\gradlew.bat run
```

첫 실행은 의존성을 내려받아 시간이 걸릴 수 있다. DB 초기화 후 **회원가입**으로 테스트 계정을 만들고 로그인한다. clone에 포함된 공용 로그인 계정은 없다. 로그인 후 지도 준비 중에는 진행 표시가 나온다.

DB·로그인 없이 지도 연결만 확인하려면 카카오 키를 준비한 뒤 다음을 실행한다.

```powershell
.\gradlew.bat runMapDemo
```

앱 실행 뒤 [로컬 지도 페이지](http://localhost:8080/map.html)에서 연결을 확인할 수 있다. 이전에 실행한 Python 서버가 있으면 먼저 종료한다. 다른 프로그램이 8080 포트를 쓰고 있으면 포트 충돌 안내를 확인한다.

키를 수정하거나 로딩에 실패하면 메인·편집 화면의 **지도 다시 불러오기**를 사용한다. 현재 코스와 선택 위치는 유지된다. 서버는 앱 종료 시 정리된다.

통합 앱 시작점은 `com.datecourse.app.AppLauncher`다. IntelliJ에서는 이 클래스 또는 Gradle `run`을 사용하고 Working directory를 프로젝트 루트로 지정한다. 이전 `MainApp`은 통합 앱 시작점이 아니다.

### 선택 사항: TMAP 도보 경로

메인의 **도보 경로 조회**, 편집 화면의 **도보 경로 → TMAP 도보 경로 조회**로 현재 순서의 도보 거리·시간·안내를 확인한다. 일반 사용자 창에는 appKey 입력란이 없으며 **경로 탐색 방식**에서 추천·대로 우선·최단·계단 제외를 선택한다.

개발자가 실제 도보 조회까지 확인하려면 별도의 TMAP 서비스 키를 준비한다. `TMAP_APP_KEY` 환경변수 또는 Git 제외 대상 `.local/tmap.properties`의 `tmap.app.key`를 사용한다. 키 원문을 Git·문서·채팅에 남기지 않는다. 탐색 옵션 선택은 `.local/tmap-route.properties`에 저장된다.

도보 경로는 선택적 확인 기능이다. 추천·편집의 직선 거리 반경 검사와 구분한다. **`d32bc76`에는 안내 패널의 지도 크기 변동과 두 지도 간 옵션 불일치가 남아 있다.** [[리뷰_및_구현_방향|리뷰와 다음 구현 방향]]에서 확인한다.

## 7. 자동 테스트

자동 테스트는 미리 적어 둔 예상 결과와 실제 계산·화면 동작을 프로그램이 비교하는 검사예요. `run`은 앱을 사용하려고 켜는 명령이고, `test`는 이런 검사를 실행하는 명령이에요.

프로젝트 루트에서 실행한다. 앱을 켜는 `run`과 다른 작업이다.

```powershell
.\gradlew.bat test
```

- 성공 신호: 콘솔의 `BUILD SUCCESSFUL`.
- 자세한 결과: `build/reports/tests/test/index.html`을 브라우저로 연다.
- 실제 로컬 MySQL·카카오 키·지도 서버 없이 H2와 모의 응답으로 검사한다. 의존성 다운로드를 위한 인터넷은 필요할 수 있다.
- 일부 검사는 JavaFX WebView·Swing 창을 사용하므로 Windows의 그래픽 데스크톱 환경에서 실행한다.

한 클래스만 다시 검사하려면 다음처럼 실행한다.

```powershell
.\gradlew.bat test --tests "com.datecourse.service.NextPlaceServiceTest"
```

문서 사이트 인증·대시보드 테스트는 별도 영역이다. 앱의 첫 실행을 위해 Node.js나 Cloudflare 계정을 만들 필요는 없다.

`d32bc76`의 일반 `test`에서는 실제 도보 통신 검사인 `WalkingRouteLiveTest`를 제외한다. 키·네트워크를 준비한 뒤 실제 서비스까지 확인할 때만 별도 `tmapLiveTest` 작업을 사용한다. 일반 테스트 성공과 실제 지도·API 검증을 구분한다.

## 8. 실제 화면 확인

자동 검사에서는 실제 지도·저장소 대신 시험용 환경을 쓰기도 해요. 그래서 검사 성공 후에는 내 PC의 실제 지도와 DB로도 아래 흐름을 따라가 봐야 해요.

자동 테스트 통과와 실제 DB·지도 연결 확인은 구분한다. 6단계에서 앱을 실행한 뒤 다음 순서로 확인한다.

1. 회원가입·로그인 후 지도가 표시되는지 확인한다.
2. 출발지·인원·전체 원형 범위를 선택한다.
3. **코스 만들기**에서 다음 장소의 활동·1인 가격 상한·이동 반경을 정한다.
4. 후보 최대 5곳의 상세를 열고 한 곳을 추가한다. 후보가 없으면 출발 위치·반경·가격 조건을 조정한다.
5. 장소 추가·삭제·순서 변경 후 **편집 완료**로 메인 지도에 반영한다.
6. 다시 편집해 변경한 뒤 **편집 취소하고 돌아가기**를 눌러 기존 코스가 유지되는지 확인한다.

현재 ‘편집 완료’는 메인 화면 반영까지다. **회원별 코스 DB 저장·앱 재실행 후 재조회는 아직 구현되지 않았다.**

## 현재 시연 확인

로그인 → 조건·장소 선택 → 편집 완료 → 하단 코스 저장(이름 입력) → 저장 목록 → 불러오기·수정 저장 → 앱 재시작 복원을 확인해요. 회원 DB 없이 시연 목록만 보려면 .\gradlew.bat runPilotDemo를 사용해요. 이 실행에서는 DB 저장이 불가능해요. [[현재_구현_흐름|전체 흐름]]을 함께 읽어 주세요.
