**9e59289 · 2026-11-23 앱 코드 기준.** 프로젝트 최상단에서 실행해요. 현재 기본 설정은 [[공통_접속_키|공통 접속 키]]로 API와 팀 DB 접속 정보를 가져오는 방식이에요.

## 팀 환경에서 실행

1. 최신 `master` 코드를 준비해요. 작업 중인 수정은 보존하고 팀원이 쓰는 브랜치를 강제로 초기화하지 않아요.
2. 검증 환경은 Temurin JDK 25.0.4.1과 프로젝트 Gradle Wrapper예요. `java -version`으로 현재 JDK를 확인해요. 별도 Maven 설정은 사용하지 않아요.
3. `src/main/resources/team-access.properties.example`을 `.local/team-access.properties`로 복사하고 담당자에게 받은 키를 설정해요. 실제 키를 문서나 Git에 올리지 않아요.
4. 아래 명령으로 실행해요. 지도 서버는 앱이 준비하므로 별도 정적 서버를 실행하지 않아요.

```powershell
.\gradlew.bat run
```

공통 키가 설정돼 있으면 조회 실패 시 다른 로컬 설정으로 자동 전환하지 않아요. 네트워크·키·서버 설정을 먼저 확인해요. 앱 실행만으로 공용 장소 데이터를 새로 적재하지 않아요.

## 실행과 검사 명령

| 명령 | 용도 |
|---|---|
| `.\gradlew.bat run` | 회원 DB와 연결하는 주 앱 |
| `.\gradlew.bat runPilotDemo` | 회원 로그인 없이 지도 편집을 확인하는 시안. 실제 지도 설정·네트워크는 필요 |
| `.\gradlew.bat test jar` | 기본 회귀 검사와 패키지 빌드 |
| `.\gradlew.bat tmapLiveTest` | 실제 지도·도보 서비스 검사. 설정·네트워크와 API 사용량 필요 |
| `.\gradlew.bat resetAdminPassword` | 로컬 마스킹 입력창에서 관리자 비밀번호 재설정 |
| `node --test docs/site/test/*.test.mjs` | 문서 사이트 검사 |
| `node docs/site/tools/build.mjs` | 웹 문서 빌드 |

관리자 비밀번호 재설정은 실제 연결된 DB를 변경하므로 담당자가 재설정할 때만 실행해요. 이번 검토에서는 실제 관리자 비밀번호를 다시 바꾸지 않았어요.

## 별도 로컬 DB를 쓰는 경우

공통 키 환경과 구분해서 준비해요. `data/sql`의 스키마와 `DbSettings` 개별 설정 예제를 확인하세요.
저장·확장 스키마는 저장소 초기화 코드와 각 SQL의 설명을 함께 읽어야 해요. 과거 문서의 테이블 수·장소 수를 최신 공용 DB의 검증값으로 사용하지 않아요.
`05_replace_integrated_data.sql`과 적재 도구는 기존 데이터를 바꾸므로 실행 준비 과정에서 공용 DB에 임의로 적용하지 않아요.

## 직접 확인할 순서

로그인 → 출발지·인원·반경 → 후보 검색 → 두 장소 추가 → 구간·누적 시간 → 편집 완료 → 저장 → 저장 목록 이미지 → 다시 열기 → 로그아웃.
관리자는 회원 선택 → 수정 확인창 취소 → 상태 확인 → 제보 검토에서 접수 당시 값과 현재 정정 값을 비교해요.
지도 리소스가 바뀐 뒤에는 실행 중인 앱을 재시작해야 해요.
