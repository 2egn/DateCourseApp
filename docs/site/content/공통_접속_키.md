---
title: 공통 접속 키 설정
---


팀 전용 앱은 **공통 접속 키 하나**로 카카오 지도·TMAP·Google Places 키와 DB 접속 정보를 받아옵니다. DB 데이터 자체는 기존 MySQL 서버에 그대로 있습니다. MCP 문서 열람 토큰과 앱 공통 접속 키는 서로 다른 권한입니다.

## 팀원이 할 일

1. 저장소 최상단에 `.local` 폴더를 만듭니다.
2. `src/main/resources/team-access.properties.example`을 `.local/team-access.properties`로 복사합니다.
3. 프로젝트 담당자에게 받은 공통 키를 `team.access.key=` 뒤에 넣습니다. 실제 값은 Git·문서·채팅에 올리지 않습니다.
4. 앱을 다시 실행합니다. 지도·경로·DB 연결이 같은 공통 키를 사용합니다. Google 검증 도구는 API 키만 조회합니다.

```properties
team.access.key=담당자에게_받은_64자리_키
```

키에는 영문 소문자 a~f와 숫자만 들어갑니다. 대안으로 `DATECOURSE_TEAM_ACCESS_KEY` 환경변수를 사용할 수 있으며 파일보다 우선합니다.

```mermaid
flowchart LR
    A[로컬: 공통 키 하나] -->|HTTPS POST · Authorization 헤더| B[Cloudflare 서버]
    B --> C[Secrets의 API 키 3개]
    C --> D[앱 메모리에서 재사용]
```

## 동작과 오류

- API 키: `POST https://datecourseapp-team-docs.ate-ourse-pp.workers.dev/api/app/keys`
- DB 설정: 같은 서버의 `POST /api/app/database` — URL·사용자명·비밀번호만 별도 반환합니다.
- 공통 키가 설정되면 서버 조회를 우선합니다. 받은 API 키와 DB 접속 정보는 파일에 쓰지 않습니다.
- 실행 중 한 번 성공하면 메모리에서 재사용합니다. 키 교체 시 앱·검증 도구를 다시 실행합니다.
- 서버 조회 실패 시 기존 개별 키로 몰래 대체하지 않습니다. 네트워크·공통 키를 확인하고 다시 시도합니다.
- 공통 키를 설정하지 않은 기존 환경은 개별 로컬 키·환경변수를 계속 사용합니다.
- 카카오 키는 WebView가 지도를 표시할 때 전달됩니다. SDK 허용 도메인 `http://localhost:8080`은 계속 필요합니다.
- 빌드할 때 실제 TMAP 키를 JAR에 넣던 처리는 제거했고, `db.properties`도 JAR에서 제외합니다. 기존 개별 키 파일은 백업으로 남아 있지만 공통 설정이 있으면 사용하지 않습니다.
- 서버·앱의 통신이 실패하면 처음 키가 필요한 지도·경로 기능은 사용할 수 없습니다. 오류 응답에는 키가 포함되지 않습니다.

## 담당자: 서버 값 관리

Cloudflare Worker `datecourseapp-team-docs`의 Settings → Variables and Secrets에 **Secret**으로 설정합니다.

| Secret 이름 | 값 |
|---|---|
| `APP_ACCESS_KEY` | 팀에 배포할 무작위 64자리 공통 키 |
| `KAKAO_MAP_JAVASCRIPT_KEY` | 카카오 JavaScript 키 |
| `TMAP_APP_KEY` | TMAP 앱 키 |
| `GOOGLE_PLACES_API_KEY` | Google Places API 키 |
| `APP_DB_URL` | 기존 DB의 JDBC 접속 URL |
| `APP_DB_USER` | 기존 DB 사용자명 |
| `APP_DB_PASSWORD` | 기존 DB 비밀번호 |

`SESSION_KEY`, `GITHUB_CLIENT_SECRET`는 기존 문서 로그인용이므로 바꾸지 않습니다. DB 정보는 별도 DB 조회 경로에서만 반환합니다. 문서 로그인이나 읽기 전용 MCP 토큰으로는 앱 키·DB 설정을 조회할 수 없습니다.

공통 키를 가진 사람은 API 키 세 개와 DB 접속 정보를 모두 조회할 수 있습니다. 유출되면 `APP_ACCESS_KEY`와 팀원들의 로컬 설정을 교체하고 필요하면 외부 API 키도 교체합니다. 개별 API 키나 DB 정보를 교체했다면 앱을 다시 실행하면 됩니다.

## 코드 읽는 순서

1. `TeamApiKeys.accessKey()` — 공통 키 파일·환경변수 읽기
2. `TeamApiKeys.get()` → `fetch()` → `decode()` — HTTPS 조회·응답 검사·메모리 재사용
3. `TmapSettings.load()` / `MapPageServer.configuration()` — 조회한 키를 기존 기능에 전달
4. `docs/site/src/app-keys.mjs`의 `appKeys()` — 접속 키 검사 후 허용한 세 키만 반환
5. `DbSettings.load()` → `TeamApiKeys.database()` — DB 정보를 별도로 조회하고 기존 JDBC 연결에 전달
6. `tools/place-data-pilot/team_keys.py` — Google 검증용 같은 방식의 Python 구현

`static` 필드가 같은 실행 프로세스 안에서 조회 결과를 공유하고, `synchronized`가 지도·경로가 동시에 요청할 때 중복 조회를 막습니다. `Map.copyOf()`는 받은 키 목록을 이후 코드에서 수정하지 못하게 만듭니다.
