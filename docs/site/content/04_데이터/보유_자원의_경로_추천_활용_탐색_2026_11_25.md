현재 후보는 활동·가격·전체/구간 직선 반경·세부 업종·특징을 통과한 뒤 직선 거리순으로 보여요. 실제 도로 이동시간이 후보 순위를 정하지는 않아요. 기존 자료만으로도 다음 개선을 검토할 수 있어요. 아래는 탐색 결과이며 앱에 적용한 기능은 아니에요.

| 요소 | 활용 방향 | 현재 한계 |
|---|---|---|
| 다음 활동 연결성 | 활동 순서가 정해진 경우 가까운 후보 몇 곳을 비교해 뒤 단계에서 막히는 선택을 줄여요. | 사용자가 정하지 않은 활동 순서를 강제하지 않아요. |
| 추천 이유·선호 | 직선거리·가격 근거·다음 후보 수를 보여주고 거리/가격 기준을 직접 고르게 해요. | 숨은 점수·가중치와 매장 실값을 만들어내지 않아요. |
| 실제 이동 부담 | 소수 후보의 조회 결과에서 시간·환승·도보를 비교해요. | 추가 공급사 호출·지연·실패 처리와 현재 표시 범위의 응답 관리가 필요해요. |
| 교통 접근성 | 5,628곳의 최근접 역·정류장 직선거리와 역 노선명을 참고해요. | 버스 원본에 운행 노선·배차·시간표가 없어 직통·환승을 판정할 수 없어요. |
| 운영시간·시설 | 원문과 엄격히 연결된 박물관 23곳의 시간, 별도 시설 사실 45건을 참고 안내에 활용해요. | 방문시각·체류시간 입력과 예외 휴무 확인이 없어요. 주차 문구의 조건·부정·요금도 검토해야 해요. |

696개 기존 오프라인 조건에서 가까운 장소 하나씩 고르면 세 활동 선택이 535개였어요. 끊긴 161개 조건에서 각 단계의 가까운 후보 5곳까지만 비교하니 19개에 대안이 있어 총 554개 조건에서 세 활동을 이을 수 있었어요. 실제 이동 경로·이용자 완료율·최적 경로를 검증한 결과는 아니에요. 앱 추천은 바꾸지 않았고 이 실험에서 DB·공급사 API를 호출하지 않았어요.

공공 후보의 평점은 전부 미확인이며 0을 낮은 평가로 쓰면 안 돼요. 날씨·고도·혼잡도·실제 방문/선호 학습 기록도 현재 자원에 없어요. 저장한 코스를 방문·만족으로 추정하지 않아요. 외부 영업시간·평점용 임시 모델은 있지만 실제 조회와 추천 연결은 아직 없어요.

먼저 연결 가능성과 추천 이유, 다음으로 명시적인 정렬 선호를 검토하고 실제 시간 비교는 소수 후보 요청 흐름부터 정하는 방향이 적합해요. 저장소 `docs/research/route-resource-exploration-2026-11-25.md`에 코드 경로·수량·입력 SHA·재현 명령·구현과 구분한 제안을 정리했어요. 재현 도구는 일반 앱 빌드에 포함하지 않는 `tools/catalog-ops/RouteResourceProbe.java`예요. 전체 Java 398개·보관 2개와 탐색 실행을 통과했어요.

현재 미사용 여가 원본은 6,032건이고 볼링장 54·탁구장 128·수상/해양 레저업 77건 등이 있어 활동 다양화 후보가 돼요. 헬스장·독서실 등도 섞여 있어 전부 문화로 바꾸지 않아요. 현재 확장·앱 활동 분류에는 넣지 않았고 세부 업종 선별·가격·분류 기준 검토가 먼저예요.

보관 상가 원본의 건물·층 정보도 활용 후보예요. 현재 상가 후보 5,060곳 중 층 정보는 3,191곳, 정확한 건물 번호로 식사와 카페가 함께 있는 그룹은 173개예요. 제공 CSV는 같은 업소 ID 157,296개를 담고 있지만 건물 번호가 지수 표기로 축약돼 있어 건물별 묶기에 쓰면 안 돼요. 좌표 차이는 원본 대비 최대 약 5mm로 작았고 이번 확장은 보관 원본을 사용했어요. 같은 건물이 실내 연결·접근성·이동시간 0분을 보장하지는 않아요.

원본·DB·현재 API의 미사용 필드를 찾는 후속 요청은 [[04_데이터/분류_세분화와_미사용_원본_필드_2026_11_25|분류 세분화와 원본 필드 검토]]에서 별도로 정리했어요. 이 문서의 연결성 실험은 기존 정보로 새 판단을 만드는 다른 범위의 기록이에요.
