코드를 읽는 대표 순서를 폴더 이름에 표시해요. 실제 화면 이동을 강제하는 단계는 아니며 저장 목록·내 페이지·관리자는 필요할 때 바로 접근해요.

| 순서 | Java·FXML 공통 경로 | 역할 |
|---|---|---|
| 01 | `com/datecourse/page/_01step_planner/` | 출발지·공통 조건·전체 코스 조율 |
| 02 | `com/datecourse/page/_02step_editor/` | 장소·조건·방문 순서 편집 |
| 03 | `com/datecourse/page/_03step_saved/` | 저장 목록·코스 다시 열기 |

`account`, `review`, `common`은 독립·공통 기능이라 번호를 붙이지 않아요. Java와 FXML은 각각의 표준 소스 폴더 안에서 같은 경로를 사용해요.

<details>
<summary>보관·삭제·유지 기준</summary>

- `archive/legacy-ui/`: 미연결 관리자·커뮤니티·추천 편집 예제, 관련 가짜 자료·모델·변환기, 단독 실행 예제. Java 19개·FXML 3개·검사 2개를 원래 경로 구조로 보관했어요.
- 삭제: 없는 로그인 FXML을 여는 `MainApp`, 픽셀용 `FakeMapData`, 가짜 수를 만드는 `PlaceCountService`. 현재 코드·FXML·빌드 참조가 없어요. 삭제 전 코드는 `879679e`로 복구할 수 있어요.
- 유지: 실제 회원 관리·정정 검토, 지도·카메라·공급사 검증, DB 유지보수, 운영 자료·SQL·수집 및 검증 기록. 외부 정보 모델의 저장 금지 계약도 유지해요.

보관 목록·지문·복원 방법은 저장소 `archive/legacy-ui/README.md`와 `inventory.json`에 있어요. archive는 기본 빌드·JAR에 포함하지 않아요. 기존 `docs/archive/`는 과거 문서 링크를 유지해요.

</details>

<details>
<summary>검증 범위</summary>

앱 Java 365개·유지보수 3개가 통과했어요. 기존 370개 중 예제 전용 2개를 보관해 기본 검사는 368개예요. 보관 예제도 별도 소스 집합에서 컴파일하고 두 검사 모두 통과했어요. 실제 앱 검사 누락이나 실패로 인한 감소는 아니에요. 새 JAR의 실제 화면 FXML 5개와 컨트롤러 연결을 확인했고 보관·삭제한 코드는 포함되지 않아요. 운영 DB·API 호출·게시 사이트 배포는 이 정리에서 수행하지 않아요.

</details>
