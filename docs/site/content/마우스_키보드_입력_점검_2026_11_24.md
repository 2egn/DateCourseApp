지도·저장 화면에서 재현된 입력 오류 세 건을 수정했어요. 아래 추가 UX 제안은 검토 내용이며 구현 완료로 표시하지 않아요.

## 수정한 오류

| 재현 상황 | 수정 |
|---|---|
| 지도 보기 전환 버튼과 마커가 겹침 | 지도 위 컨트롤 → 마커 → 경로 순으로 입력을 처리해요. 지도 밖 요소와 링크·버튼 입력은 마커 제스처가 가로채지 않아요. |
| 저장 이미지가 늦게 도착하는 중 장소 행 클릭 | 미리보기 확인 상태를 별도로 관리해요. 확인 중에는 지도 불러오기를 비활성화하고, 저장 이미지가 확인되면 명시적인 불러오기 버튼을 유지해요. 선택한 장소는 실제 지도를 연 뒤 포커스해요. |
| 경로 상세를 연 뒤 Tab 탐색 | 닫기 버튼의 키보드 탐색 상태를 복원해요. 닫았다 다시 열어도 접근할 수 있고 Esc·닫기 클릭으로 닫혀요. |

`map.js.pointerFrom`과 문서 입력 처리에서 컨트롤을 제외해요. `SavedCourseController.previewLoading`은 기존 요청 번호·회원 검사를 통과한 완료 응답에서만 해제해요. 예전 `onToggleMap`도 같은 전환 규칙을 따르게 했어요. `itinerary-rail.js.openRouteDetails`에서 닫기 버튼을 복원해요.

## 추가 UX 검토 — 아직 미구현

| 우선순위 | 제안 | 이유 |
|---|---|---|
| 높음 | 저장 장소 표를 방향키로 선택하고 Enter로 지도 포커스 | 현재 표는 선택 모델을 끄고 마우스 행 클릭으로만 연결해요. 키보드로 같은 동작에 접근하기 어려워요. |
| 높음 | 상세·확대 이미지를 닫으면 열었던 버튼으로 포커스 복귀 | 지도 단독 상세와 확대 이미지의 닫기 동작은 이전 조작 위치를 보관하지 않아요. 닫힌 요소에 포커스가 남을 수 있어요. |
| 중간 | 편집의 ‘내 코스’ 목록도 Enter로 상세 열기 | 후보 목록은 Enter를 지원하지만 내 코스는 마우스 더블 클릭·별도 상세 버튼을 사용해요. 같은 목록 조작을 맞추는 편이 좋아요. |
| 중간 | 모든 주요 버튼의 키보드 포커스 테두리 통일 | 버튼의 배경·테두리를 테마에서 덮어쓰므로 키보드 위치가 충분히 뚜렷한지 확인하고 보강할 필요가 있어요. |

현재 검색 결과의 방향키·Enter·Esc, 상세의 Esc, 이미지 확대의 Enter/Space와 Esc, 목록 마우스 선택과 지도 드래그 구분은 이미 구현돼 있어요. 새 단축키는 텍스트 입력·슬라이더·스크롤의 기본 조작을 가로채지 않도록 화면별로 제한하는 게 좋아요.

## 검증

실제 화면 스크립트와 모의 SDK로 버튼·마커 중첩, 호버 억제, 경로 상세의 재개방·키보드 접근을 검사해요. 저장 PNG 응답을 지연한 검사에서는 장소 클릭이나 예전 전환 메서드로 명시적 불러오기를 건너뛰지 않는지 확인해요. 실제 공급사 호출·운영 DB 변경은 포함하지 않아요.
