# 운영 지도 카메라 이동

비교 시안에서 확인한 이동 정책을 공통 조건과 코스 편집의 동일한 지도 페이지에 적용했다.

## 책임

- `CameraMotionPolicy`는 Java에서 이동 의도와 화면 기준 측정값을 받아 이동 방식, 배율, 목표 시간을 결정한다.
- `MapBridge.decideCameraTransition`은 이 결정을 동기적으로 전달한다. SDK 호출이나 화면 변경은 하지 않는다.
- `camera-motion.js`는 SDK 좌표 측정과 실행, 마지막 요청 하나의 대기를 담당한다. 대기 요청은 SDK idle 이후 다시 측정한다.
- `map.js`의 출발지, 후보 포커스, 상세 카드, 전체 범위/코스, 도보 경로 보기 모두 같은 제어기를 사용한다.

가까운 선택은 배율을 유지하며 panTo로 이동한다. 중심과 배율을 함께 바꿀 때는 SDK jump를 사용하며, 미지원 환경에는 기본 API 조합을 사용한다. 사용자별·장소별 예외와 지연 후 강제 재중심 코드는 두지 않는다.

## 입력 처리

공통 반경, 다음 장소 반경, 기존 구간 반경 모두 드래그 중에는 원을 즉시 갱신하고 확대를 억제한다. 범위가 화면을 벗어날 때만 축소하며, 놓으면 최종 범위를 맞춘다. 휠이나 지도 드래그는 자동 이동 대기를 취소한다. 자동 이동 요청은 아직 실행하지 않은 휠 확대/축소 요청을 취소한다.

OS의 reduced-motion 설정은 즉시 이동으로 반영한다. 초기화는 대기를 비우고 기본 위치·배율로 복원한다. 화면 크기 변경 시 SDK relayout을 위한 현재 중심 복원은 유지한다.

## 확인

```powershell
.\gradlew.bat test
.\gradlew.bat tmapLiveTest
.\gradlew.bat runPilotDemo
```

오프라인 검사는 기존 핀·상세 카드 인터랙션과 마지막 요청/수동 취소/반경 드래그/초기화를 검증한다. 실제 지도 검사는 Kakao SDK 최종 위치·대기 해제·반경 놓기와 TMAP 도보 경로 및 편집 폼 누적 시간을 확인한다. SDK 이동 좌표는 화면 픽셀 단위로 반올림될 수 있어 실제 위치 검사는 수 미터의 오차를 허용한다.

지도 서버가 시작할 때 리소스를 보관하므로 이미 실행 중인 앱은 재시작해야 한다. 장거리 이동의 타일 공급과 애니메이션 연속성은 기존 SDK와 네트워크의 영향을 받는다.

## 비표시·크기 변경 시 포커스 수정 (2026-11-15)

크기가 0인 지도에 범위 맞춤을 요청하면 기존 계산은 여백을 뺀 길이를 1px로 대신 계산했다. 회귀 검사에서 배율 5가 14로 잘못 바뀌는 것을 재현했다. JavaFX WebView에는 비표시 상태에서도 기본 WebKit 크기가 잡힐 수 있으므로 DOM 크기 검사만으로 실제 표시 준비를 판단하지 않는다.

- `MapViewportLifecycle`는 JavaFX 부모 화면과 창이 표시되고 WebView 크기가 생긴 뒤 페이지를 로드한다. 준비 전에 전달한 코스는 PlannerMap에 보관했다가 기존 준비 콜백에서 렌더링한다.
- SDK 지도 생성도 실제 DOM 영역이 카메라 여백보다 커질 때까지 기다린다.
- 카메라는 비표시/너무 작은 영역에서 계산하지 않고 마지막 목표를 보관한다.
- ResizeObserver와 창 크기 변경 이벤트를 통해 SDK relayout을 먼저 수행하고, 중심을 보존한 뒤 좌표를 계산한다. 레이아웃 갱신 중 동기 idle 이벤트는 대기 요청을 실행하지 않는다.
- 기존 80ms 뒤 별도로 카메라 대기를 지우던 크기 변경 코드는 공통 어댑터로 통합했다. 지도 크기 변경으로 마지막 사용자 선택을 잃지 않는다.

검증은 0 크기에서 과도한 축소 방지, 보이는 상태로 전환한 뒤 마지막 요청 복원, 숨겨진 부모 아래의 페이지 로드 지연, 실제 Kakao 지도에서 숨김→표시 및 2560px 창 요청 후 실제 WebView 너비가 2000px 이상으로 변한 것을 기다린 뒤 중심·배율 유지를 포함한다. 생성된 실제 화면에서 서면 중심과 전체 타일 영역 표시를 확인했다.

실행 중인 앱은 캐시된 지도 스크립트를 교체하기 위해 재시작해야 한다.

## 반경 편집과 새 장소 구간 포커스

반경 편집 완료 시 현재 편집 중인 원의 중심과 크기에 맞춘다. 공통 조건은 파란 전체 원,
세부 조건은 초록 원(선택 구간 또는 마지막 장소 기준)을 사용한다. 큰 전체 원이 작은 세부 원의 확대를 막지 않는다.
드래그 중 확대 억제와 손을 놓은 후 맞춤은 유지하며, ‘두 범위 보기’는 두 원을 함께 보여준다.

장소 추가가 완료되면 Java 컨트롤러에서 새 구간 인덱스로 맞춤을 요청한다.
첫 장소는 출발지→첫 장소, 이후는 직전 장소→추가 장소를 표시한다.
전체 원, 이전 구간, 다른 후보는 새 구간의 맞춤 좌표에서 제외한다.
도보 경로가 준비된 경우 해당 구간의 굽은 경로 좌표도 포함하고, 계산 중에는 두 지점을 기준으로 맞춘다.
도보 응답 자체는 카메라를 다시 이동시키지 않는다.

검증: 전체 회귀 테스트와 실제 Kakao SDK에서 새 구간 중심/배율, 작은 세부 원 맞춤,
애니메이션 대기 해제를 확인했다. 실제 지도 검사는 지도 카메라만 변경하며 DB 데이터를 수정하지 않는다.
