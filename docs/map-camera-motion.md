# 운영 지도 카메라 이동

비교 시안에서 확인한 이동 정책을 공통 조건과 코스 편집의 동일한 지도 페이지에 적용했다.

## 책임

- `CameraMotionPolicy`는 Java에서 이동 의도와 화면 기준 측정값을 받아 이동 방식, 배율, 목표 시간을 결정한다.
- `MapBridge.decideCameraTransition`은 이 결정을 동기적으로 전달한다. SDK 호출이나 화면 변경은 하지 않는다.
- `camera-motion.js`는 SDK 좌표 측정과 실행, 마지막 요청 하나의 대기를 담당한다. 대기 요청은 SDK idle 이후 다시 측정한다.
- `map.js`의 출발지, 후보 포커스, 상세 카드, 전체 범위/코스, 도보 경로 보기 모두 같은 제어기를 사용한다.

가까운 선택은 배율을 유지하며 panTo로 이동한다. 중심과 배율을 함께 바꿀 때는 SDK jump를 사용하며, 미지원 환경에는 기본 API 조합을 사용한다. 사용자별·장소별 예외와 지연 후 강제 재중심 코드는 두지 않는다.

## 입력 처리

공통 반경, 다음 장소 반경, 기존 구간 반경 모두 드래그 중에는 원을 즉시 갱신하고 확대를 억제한다. 범위가 화면을 벗어날 때만 축소하며, 놓으면 최종 범위를 맞춘다. 휠이나 지도 드래그는 자동 이동 대기를 취소한다. 자동 이동 요청은 아직 실행하지 않은 휠 확대/축소 요청을 취소한다.

OS의 reduced-motion 설정은 즉시 이동으로 반영한다. 초기화는 대기를 비우고 기본 위치·배율로 복원한다. 화면 크기 변경 시 SDK relayout을 위한 현재 중심 복원은 유지한다.

## 확인

```powershell
.\gradlew.bat test
.\gradlew.bat tmapLiveTest
.\gradlew.bat runPilotDemo
```

오프라인 검사는 기존 핀·상세 카드 인터랙션과 마지막 요청/수동 취소/반경 드래그/초기화를 검증한다. 실제 지도 검사는 Kakao SDK 최종 위치·대기 해제·반경 놓기와 TMAP 도보 경로 및 편집 폼 누적 시간을 확인한다. SDK 이동 좌표는 화면 픽셀 단위로 반올림될 수 있어 실제 위치 검사는 수 미터의 오차를 허용한다.

지도 서버가 시작할 때 리소스를 보관하므로 이미 실행 중인 앱은 재시작해야 한다. 장거리 이동의 타일 공급과 애니메이션 연속성은 기존 SDK와 네트워크의 영향을 받는다.
