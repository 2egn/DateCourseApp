# 운영 장소 적재·갱신 (2026-11-15)

## 실행 방법

- `./gradlew.bat previewPlaceImport`: 패키징된 386곳과 공공 속성을 검증하고 정규화 지문을 출력한다. DB 연결이나 쓰기를 하지 않는다.
- `./gradlew.bat importPublicPlaces`: 기존 팀 DB 설정으로 추가 테이블을 준비하고 전체 자료를 하나의 트랜잭션으로 반영한다. 이후 운영 조회와 관리자 overlay 조회를 검증한다.

자료 소유자 키는 `busan-public-places`, 생성 시각은 공공 속성 자료의 generatedAt을 사용한다. 같은 버전을 재실행하면 기존 장소 번호와 수정 이력을 중복 생성하지 않는다. 실행 이력은 매번 기록한다.

## 저장 구조

기존 data_records는 전역 장소 번호 발급을 위해 유지한다. 새 장소에는 source_file=managed_place_catalog_v1인 최소 식별 행을 추가한다. 기존 integrated_places.csv 행을 덮어쓰거나 삭제하지 않는다. 관리자 정정 테이블과 저장 코스 테이블도 적재 대상이 아니다.

| 테이블 | 내용 |
| --- | --- |
| place_catalog_lock | 동시에 실행된 적재의 직렬화 잠금 |
| place_catalog_sources | 자료 소유자별 마지막 성공 생성 시각·내용 지문 |
| place_catalog_imports | 성공 적재의 신규·수정·재활성·비활성·유지 집계 |
| place_catalog_entries | 공공 고유 ID, 기존 전역 record_id, 출처 소유자, 현재 모델 JSON·지문·활성 상태 |
| place_catalog_revisions | 실제 변경 시점의 모델 JSON과 활성 상태 이력 |

기본 정보·가격 근거·속성·외부 연결·항목별 근거는 버전 관리되는 Place JSON에 함께 보존한다. 이번 단계에서는 속성별 SQL 필터링용 테이블로 쪼개지 않는다. 추천은 기존 Java 필터를 사용한다. Google 상세 조회용 객체는 적재 입력으로 사용하지 않는다.

## 갱신 규칙

1. 내부 시연 ID와 recordId 대신 externalIds.public을 영구 장소 키로 사용한다. 없는 경우 유효한 placeId를 사용한다.
2. 입력 순서와 시연용 recordId에 영향을 받지 않는 내용 지문을 생성한다. 가격 단위·근거와 속성의 미확인 상태도 보존한다.
3. 빈 전체 자료, 중복 ID, 잘못된 좌표·분류·출처, Google 제공 가격이나 관리자 정정 결과의 원본 재적재를 거부한다.
4. 같은 생성 시각의 다른 내용 또는 더 오래된 생성 시각으로 덮어쓰지 않는다. 수정된 자료는 새 생성 시각으로 발행한다.
5. 새 ID는 전역 번호를 한 번만 발급한다. 내용 변경은 같은 번호로 갱신한다. 변하지 않은 항목의 수정 이력은 늘리지 않는다.
6. 이번 전체 자료에 빠진 동일 소유자의 장소는 비활성화한다. 삭제하지 않으며 다시 나타나면 같은 번호로 재활성화한다. 다른 자료 소유자의 장소는 비활성화하지 않는다.
7. 소유자가 다른 동일 ID는 자동 병합하지 않는다. 충돌이나 SQL 오류가 나면 적재 실행 이력·새 번호 행·장소 변경·수정 이력을 모두 롤백한다. DDL로 준비된 빈 테이블은 남을 수 있다.
8. 같은 자료를 동시에 넣어도 DB 행 잠금으로 직렬화하며 중복 생성하지 않는다.

## 운영 조회와 호환

PlaceRepository는 성공한 카탈로그가 있으면 활성 카탈로그를 읽는다. 기존 통합 목록과 합치지 않으므로 같은 지역의 중복 후보를 만들지 않는다. 아직 카탈로그가 없거나 성공한 적재가 없으면 기존 integrated_places.csv 경로를 유지한다. 조회 자체가 테이블을 생성하거나 자료를 적재하지는 않는다.

현재 새 카탈로그 버전은 서면 중심 386곳이다. 기존 127곳을 보존한 확대 결과는 [확대 기록](dataset-expansion-2026-11-16.md)을 참고한다. 이를 적재한 DB 모드의 추천 대상은 이 활성 카탈로그이며 기존 6,139곳 전체가 새 모델로 변환됐다는 뜻은 아니다.

카탈로그가 손상되면 오류로 처리하며 과거 자료로 조용히 대체하지 않는다. 한 조회 SQL로 성공한 자료와 활성 행을 함께 읽어 적재 중간 상태가 노출되지 않게 한다.

## 관리자 정정·저장 코스

관리자 정정은 공공 ID를 키로 하는 별도 overlay다. 원본을 5,000원에서 9,000원으로 갱신해도 관리자 정정 7,000원은 유지된다. 원본 저장소에서는 9,000원, 앱에서 overlay 적용 후에는 7,000원이다. 어느 값을 쓰는지 구분할 수 있도록 근거도 유지한다.

기존 저장 코스는 저장 당시 장소·가격·근거의 스냅샷을 읽는다. 적재 작업이 저장 코스 내용을 갱신하지 않는다. 비활성화된 장소의 과거 저장본도 삭제하지 않는다. 이름·주소 정정 시 외부 연결을 재검토 상태로 바꾸는 기존 규칙도 유지한다.
