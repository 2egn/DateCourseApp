# 확장 가능한 필터 UI

## 사용 흐름

회색 세부 조건 접기 바 대신 슬라이더 아이콘과 강조 테두리가 있는 필터 설정 버튼을 제공한다. 선택 개수는 버튼에 표시하고, 편집 영역을 닫아도 선택한 조건의 칩을 최대 3개 보여준다. 칩을 누르면 해당 조건만 해제하고 나머지 조건은 유지한다. 3개를 넘으면 더 보기에서 전체 선택을 확인한다.

버튼을 열면 종류·업종 / 가격 기준 / 특징 / 선택한 필터를 전환해 편집한다. 카테고리 하나씩 표시하며 긴 항목은 공통 FormScrollPane 안에서 스크롤한다. 전체 조건 폼을 길게 늘리지 않는다. 열린 상태의 상단에는 이 조건으로 검색 버튼을 표시한다. 검색하면 필터 편집을 접고 기존 후보 검색 흐름을 사용한다. 닫힌 상태에서는 기존 후보 검색 버튼을 사용한다. Escape로 편집 영역을 접을 수 있다.

선택 변경은 검색 조건을 수정하며 후보 갱신은 검색 버튼으로 수행한다. 개수는 적용 완료 건수가 아닌 선택 개수로 표시한다. 초기화는 세부 조건만 지우고 인원·가격 상한·반경은 유지한다.

## 구조

`ExpandableFilterPane`은 검색 모델과 독립적인 JavaFX 컴포넌트다.

- `Section(id, title, description, content, selectedCount)`을 등록해 카테고리를 추가한다.
- `Selection(id, label, remove)`으로 선택 칩과 해제 동작을 제공한다.
- 검색과 전체 해제는 외부 콜백으로 연결한다.
- 고유 ID를 검사하며 카테고리를 전환해도 기존 컨트롤과 선택을 유지한다.

`RouteEditorController`는 기존 세부 필터 컨트롤을 종류/가격/특징 섹션으로 등록하고 현재 조건을 선택 칩으로 변환한다. 검색 기준과 확인 자료 처리, 활동별 선택 기억은 기존 모델을 그대로 사용한다. 필터 UI 자체를 늘리기 위해 레이아웃 분기를 추가할 필요는 없다.

## 검증

회귀 테스트 286개 및 jar 생성이 통과했다. 접힌 상태의 선택 개수/칩 표시, 특정 조건 해제 시 다른 조건 유지, 더 보기, Escape, 검색 후 접기, 40개 항목의 새 카테고리를 등록해도 스크롤 편집 영역 크기 유지, 1440/1100 크기의 렌더링을 확인했다.

UI 검증 이미지는 build/ui-preview/filter-entry-and-chips.png, filter-features-editor.png, filter-compact-editor.png에 생성한다. 이번에는 Windows 화면 캡처 세션을 사용하지 않았다.

실지도 추가 재검사는 실행 중인 앱의 8080 포트 점유로 4개 중 3개가 시작하지 못했다. 독립 포트에서도 SDK 로딩이 실패해 완료하지 못했다. 포트 변경 시도는 원복했으며 기본 앱 설정은 유지한다. 기존 지도 코드와 API 호출 방식은 이 변경에 포함하지 않았다.

## 분류 색과 후보 종류 표시

카테고리 등록 정보에 Tone을 지정하고, 선택 칩은 sectionId로 해당 카테고리 색을 공유한다. 종류·업종은 파랑, 가격은 황금색, 특징은 초록색의 옅은 배경과 테두리를 사용한다. 편집 중인 영역도 같은 계열의 색을 사용한다. 색 이외에 명칭과 선택 개수도 유지한다. 새 그룹은 색을 지정하지 않으면 중립색을 사용한다.

후보 리스트에는 특징 유무와 관계없이 식사·냉면/밀면, 카페, 문화·도서관처럼 실제 등록된 종류를 표시한다. 등록된 세부 분류가 없으면 큰 분류만 표시하고 카페·카페 같은 중복을 피한다. 특징은 종류 뒤에 함께 표시하며 긴 내용은 툴팁으로 확인할 수 있다.
